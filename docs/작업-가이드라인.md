## 1. 꼭 지킬 원칙 5가지

1. **계획대로, 한 번에 하나.** 지금 Task와 지금 브랜치만 본다. 계획에 없는 기능이 떠오르면 만들지 말고 개발일지의 "나중에" 칸에 적는다.
2. **"됐어요"보다 증거.** Claude가 끝났다고 하면 테스트 실행 결과(통과 개수)나 화면을 직접 확인한다. 확인 못 한 것은 끝난 게 아니다.
3. **비밀 값은 내 손으로만.** API 키·DB 주소는 `.env` 파일과 Vercel 대시보드에 직접 입력한다. Claude 채팅창에 붙여넣지 않는다.
4. **AI 실수는 바로 기록.** 실수를 잡은 순간이 "AI 활용 과정"(15점)의 재료다. 고친 뒤가 아니라 발견한 즉시 적는다.
5. **30분 규칙.** 30분 이상 막히면 개발일지에 적고, 기획서 13장의 대안으로 넘어간다.

## 3. Claude Code와 일하는 법

### 승인 버튼 누르기 전에

- 무엇을 실행하려는지 한 번 읽는다. 모르는 명령이면 "이 명령이 뭘 하는지 설명해 줘"라고 묻는다.
- **거절할 것**: 파일·폴더 대량 삭제, `git push --force`, `main`에 직접 커밋, `.env` 내용이나 키 값을 화면에 출력하는 명령, 계획에 없는 패키지 설치.

### 멈췄을 때 할 일 (계획의 "실행 방식" 절)

| 멈춘 이유 | 내가 할 일 |
| --- | --- |
| 사람이 할 단계(테스트 30개, 설명서 확정, 레퍼런스 등) | 직접 하고 "끝났어, 이어서 해 줘" |
| `git push`·PR·병합 확인 | 변경 파일 목록과 커밋 메시지를 읽고 승인 |
| 콘솔 설정(Vercel 환경 변수, Neon, 지역) | 브라우저에서 직접 설정 후 결과만 알려 주기 |
| 계획과 실제가 다름 | Claude의 제안을 읽고 선택. 결정이면 결정기록에 남기기 |

### 이런 요청은 이렇게

- 공식 문서가 필요한 것(Vercel 설정, OpenAI 모델 이름, Neon 설정): "공식 문서 링크와 함께 근거를 보여 줘"
- 결과가 의심스러울 때: "테스트를 다시 실행해서 출력 전체를 보여 줘"
- 범위를 벗어날 때: "그건 계획에 없으니 하지 말고 개발일지 '나중에'에 적어 줘"

## 4. AI 실수 잡기 — 특히 조심할 것

| 실수 유형 | 알아차리는 법 |
| --- | --- |
| **테스트를 고쳐서 통과시키기** | 커밋 전 diff에서 `tests/` 파일이 바뀌었는지 확인. 테스트를 바꿨다면 이유를 묻는다 |
| 없는 함수·옵션을 지어냄 | 실행하면 오류가 나거나, 공식 문서에 없다 |
| 계획과 다른 파일 위치 | 기능 폴더(`app/<기능>/`)가 아닌 곳에 새 파일이 생김 |
| 키·비밀 값을 코드에 직접 씀 | diff에서 `sk-`, `postgres://` 같은 문자열 검색 |
| 범위 밖 기능 추가 | 계획에 없는 파일·화면 요소가 생김 |
| "완료"라고 했는데 실제로는 안 됨 | 테스트 출력이나 배포 화면으로 직접 확인 |

**기록 양식** (`docs/AI-실수-기록.md`)

```markdown
## N. 제목 (YYYY-MM-DD, Task N)
- Claude가 한 것:
- 무엇이 틀렸나:
- 어떻게 발견했나: (테스트 / 직접 실행 / 문서 확인 / diff 확인)
- 어떻게 고쳤나:
- 재발 방지: (CLAUDE.md 규칙 추가 등)
```

## 5. Git·PR 체크리스트

**브랜치 시작**
- [ ] 이전 브랜치가 `main`에 병합됐다
- [ ] `git switch main && git pull && git switch -c <브랜치>` (이름은 계획의 "브랜치 전략" 표)

**커밋할 때**
- [ ] 실패하는 테스트 커밋 → 통과하는 구현 커밋 (두 번)
- [ ] Claude가 보여 준 메시지가 `타입(범위): 한국어 제목` + 무엇을·왜·테스트 형식인지
- [ ] `.env`, PDF, 조각 데이터가 포함되지 않았는지 `git status`로 확인

**PR·병합**
- [ ] 전체 테스트 통과(`pytest -v -m "not integration"`)
- [ ] PR 양식 채우기(무엇을·왜·테스트 결과·화면·관련 문서)
- [ ] Vercel 미리보기 URL에서 직접 눌러 보기
- [ ] merge commit으로 병합 → 브랜치 삭제 → 개발일지에 PR 링크
