## API (Task 15 Step 1, 2026-11-01 22:43)

- **확인 환경:** 운영 주소 `https://pyeobom.vercel.app/api/ask`에 Claude Code가 직접 요청했다(모델은 LG 벽걸이 에어컨, 지원하지 않는 모델 행만 예외).

### API 키 누락 (로컬, 2026-11-02)

- **확인 환경:** 로컬 `experiments/dev_server.py`를 `OPENAI_API_KEY`만 비우고 띄웠다(DB 등 나머지는 `.env` 그대로). 코드는 바꾸지 않았다.

| 입력 | 보낸 값 | 기대 | 상태 | error_code | 문구 | 결과 |
|---|---|---|---|---|---|---|
| API 키 누락 | LG 에어컨, `필터 청소는 어떻게 해요?` | 일반 오류 안내, 스택·키 정보 없음 | 500 | `SERVICE_UNAVAILABLE` | "일시적인 문제가 생겼어요. 잠시 후 다시 시도해 주세요" | ✅ |

- 응답 본문은 `error_code`와 `message` 두 칸뿐이다. 스택이나 키 관련 정보는 없었다(`?debug=true`로 보내도 같은 500).
- 서버 로그에는 `ask 실패: OpenAIError` 한 줄만 남았다. 오류 종류만 적고 메시지는 적지 않는다(`app/ask/routes.py`).
- 키 검사보다 질문 임베딩이 먼저 실행된다. 그래서 OpenAI 클라이언트 오류가 일반 예외 처리로 가서 500이 됐다. 같은 `SERVICE_UNAVAILABLE`이 다른 경로에서는 503이다. 화면 안내는 같아서 1차에서는 고치지 않았다(2026-11-02 개발일지 "나중에").

## 실패 시연 (Task 15 Step 2, 2026-11-02)

- **어디서:** 미리보기 배포에만 `FORCE_FAIL`을 넣고 확인했다(브랜치 `docs/final-records`의 미리보기). 운영(Production)에는 넣지 않았다(CLAUDE.md 금지 사항).
- **API:** 미리보기 `POST /api/ask` → **504 `AI_TIMEOUT`** `{"error_code":"AI_TIMEOUT","message":"답변이 늦어지고 있어요. 잠시 후 다시 시도해 주세요"}`. AI를 호출하지 않고 바로 실패를 흉내 낸다.
- **같은 시각 운영:** 같은 질문 → 200, `found: true`. 운영에는 영향이 없었다.
- **화면:** 오류 카드에 위 문구와 "다시 시도" 버튼이 나오는 것을 확인했다(위 표).
- **정리:** 확인한 뒤 사용자가 Preview 환경 변수에서 `FORCE_FAIL`을 지웠다.
