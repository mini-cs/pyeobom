- 이름: 실험 이름 "임베딩 large 다시 해 보기", 노션 단계 "v1.97"(사용자 결정 2026-11-23 밤)
- 배경(사용자 결정 2026-11-23 밤): v1.9에서 응답 시간 하나로만 미채택된 임베딩 large(결정기록 036, 리포트 `docs/평가/embedding-large.md`)를 다시 해 본다. 11/24에는 결론(채택 후보)까지만 하고, 운영 반영은 2차 뒤에 따로 한다
- 이 미리 재기는 **시간만** 본다. 채택 여부를 정하지 않는다. "너무 오래 걸림" 선은 이 결과를 사용자가 본 뒤, 4단계를 측정하기 전에 정한다
  - (정정 2026-11-23: 선은 4단계 시간을 본 뒤 사람 판정 전에 정한다 — 아래 측정 전 결정 3. 채팅 Claude가 두 번째 지시에서 이 줄을 고치라고 하지 않음)
- 문장: 평가 세트가 아닌 미리 보기 문장 20개(`measure/refine_preview.csv`, SHA-256 `10af0c4f…`, 결정기록 039). 확인용 세트는 열지 않는다
- 비교: 운영(`m0`, `chunks`, `text-embedding-3-small`)과 임베딩 large(`emb_large`, `bundle_chunks` 332행, 질문도 `text-embedding-3-large` 1536). 답변 모델·프롬프트·진단 규칙은 운영 그대로(`measure.stage2`). 코드 수정 없음
- 답 글·설명서 글은 이 리포트에 넣지 않는다. 원자료(결과 CSV·settings·판정 목록·원래 출력)는 `measure/out/emb-retry-preview/`(git 밖)

## 측정 전 결정(2026-11-23 밤)

1. 일정(사용자): 11/24에는 결론(채택 후보)까지. 운영 반영은 2차 뒤에 별도 계획으로
2. 미리 재기 먼저(사용자): 평가 세트가 아닌 문장으로 시간만 잰 뒤 진행. 채택 여부는 미리 재기로 정하지 않음
3. 시간 선(사용자)
   - 4단계 답을 만든 뒤 자동으로 잰 시간을 보고, 사람 판정 전에 사용자가 정한다
   - 결과를 본 뒤 정하는 선이므로 프로젝트 규칙("판단 기준은 측정 전에")의 명시적 예외. 결론 한계에 적는다
   - 채팅 Claude는 "4단계 전에 고정: 답변 AI 밖 +0.5초 이하 그리고 전체 +1.5초 이하"를 추천했고, 사용자는 4단계 시간을 보고 정하기로 함
   - 선례: v1.9 응답 시간 세는 법을 자동 값을 본 뒤·사람 판정 전에 정함(결정기록 036)
   - (덧붙임 2026-11-24 00:17, 사용자 결정) 선: 전체만, `latency_ms` 평균 차이(large − 운영) +500ms 이하. 세 세트 합침·두 회차 합침·오류·규칙으로 막힌 행 제외·행 수 가중. 답변 AI 밖 선은 두지 않음. 근거는 결정기록 036의 0.5초와 같은 선. 본 것은 4단계 시간 숫자만 → [결정기록 041 덧붙임](../결정기록/041-임베딩-large-다시-측정-전-결정.md#덧붙임-시간-선4단계-시간을-본-뒤판정-전)
4. 시간 세는 법(채팅 Claude 제안, 지금 고정)
   - 전체: `latency_ms` 평균 차이(large − 운영), 두 회차 합침, 오류·규칙으로 막힌 행 제외(v1.9·v1.96과 같음)
   - 답변 AI 밖: (`latency_ms` − `llm_ms`) 평균 차이, 같은 방식
   - 4단계 뒤에는 선(숫자)만 정한다
5. 선을 정할 때 사용자에게 보이는 것(채팅 Claude 제안, 지금 고정)
   - 4단계 시간 숫자만(회차별·합, 전체·답변 AI 밖)
   - found 수·5위 안 수·답 글·판정지는 선을 커밋한 뒤에 연다
