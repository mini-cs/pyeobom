# 2차 상호 테스트(U9) 기록

## 개요
- 테스터: 코드 A·B·C·D(모두 친구). 이름·이메일은 적지 않는다. 강사님은 발표 때 따로 테스트하신다
- 방법: 운영 주소에서 노션 따라 하기 가이드(7단계)를 보며 혼자 써 본 뒤, 구글 설문(10문항, 이메일 수집 안 함)에 답한다
- 안내: 2026-11-26 16시 10분쯤 A·B·C에게 보냄, D는 그 뒤. 마감 2026-11-26
- 근거: 계획 덧붙임 C-1(참가자 코드별로 쓴 시간, 나온 문제, 고쳤는지와 그 이유를 적고, 고친 것은 리포트 "안정성"에 옮긴다)

## 정리 기준 (2026-11-26 사용자 승인)
- 정한 때: 채팅 Claude가 응답 내용을 모른 채 초안을 썼고, 사용자가 응답 1건이 들어와 그 내용을 본 뒤 승인했다. 나머지 응답을 보기 전에 이 파일로 커밋한다
- 설문 문항은 응답이 들어오기 시작한 뒤 바꾸지 않는다
- 걸린 시간: 설문 7번 값을 "본인 어림"으로 적는다(측정값이 아님)
- 나온 문제는 네 가지로 나눈다
  1. 흐름 막힘: 로그인이나 요청을 끝내지 못함
  2. 이상하거나 틀린 답
  3. 헷갈리는 문구·화면
  4. 그 밖의 요청
- 코드 동결(2026-11-30 밤) 전에 고치는 것: 1, 보안·개인정보 문제, 3 중 문구 수준의 작은 것
- 기록만 하는 것: 2(PRD.md 4.3 "하지 않을 것"에 따라 검색 품질 개선은 2차 범위 밖), 4, 3 중 화면 구조를 바꿔야 하는 것
- 숫자: 4명이라 비율·평균을 내세우지 않고 "몇 명"으로만 적는다
- 후 측정 ②: 마감까지 실제 모델 요청이 0건이면 "요청 0건이라 못 함"으로 기록하고, 테스터에게 요청을 따로 부탁하지 않는다. 개선 판정은 후 측정 ① 결과로 이미 정해져 있다
- 운영 기록(계정·요청 수, 웹훅 응답)은 채팅 Claude가 Supabase를 읽기만 해서 확인한다. 이메일·사용자 번호는 적지 않는다
