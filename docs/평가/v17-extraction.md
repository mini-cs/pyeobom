## 판단 기준 (설계 7절 그대로, 측정 전 확정, 결과를 본 뒤 바꾸지 않음)

- "N문장 넘게 떨어지지 않음"은 같은 실행 안의 비교 대상과 견준다.
- 검색 적중은 함정을 빼고, 사람 판정 정답은 함정을 포함한 전체로 센다(결정기록 029와 같음).
- %p는 분모에 맞춰 문장 수로 바꾸고 올림한다.

### A. 쪽 표시 지우기: 나빠지지 않으면 채택 (비교 대상: 운영 그대로)

- A-1 (1단계, 사용자 결정)
  - 30문항 5위 안이 운영보다 1문항 넘게 떨어지지 않음
  - 개발용 P 세트 5위 안이 운영보다 1문장 넘게 떨어지지 않음
- A-2 (3단계, 사용자 결정): 5C 확인 3회 모두 찾음
- A-3 (회귀, 사용자 결정 2026-11-16)
  - 3단계 개발용 사람 판정 정답이 운영보다 1문장 넘게 떨어지지 않음, 환각 0
  - 1차 30문항 사람 판정이 운영보다 2문항 넘게 떨어지지 않음, 환각 0
  - 이어지는 질문 정답이 운영보다 1턴 넘게 떨어지지 않음, 환각 0
  - 4단계를 여는 경우에만: 확인용 5위 안과 사람 판정 정답이 각각 운영보다 1문장 넘게 떨어지지 않음, 환각 0
  - 4단계를 열지 않는 경우: 30문항과 이어지는 질문은 6절 4단계의 "여는 조건"에 적은 실행으로 잰다.

### B. 도구·자르기: 올라야 채택 (비교 대상: 쪽 표시만 지운 것, 계획 1-4의 숫자)

- B-1 (1·2단계, 검색만)
  - 개발용 P 세트 5위 안이 15%p 이상 오름(20문장 중 3문장 이상)
  - 30문항 5위 안이 1문항 넘게 떨어지지 않음
- B-2 (3단계)
  - 개발용 사람 판정 정답이 10%p 이상 오름(21문장 중 3문장 이상), 환각 0
  - 질문당 비용이 1.5배 이하
  - 같은 실행 안 응답 시간 증가가 0.5초 이하
- B-3 (4단계)
  - 확인용 5위 안이 10%p 이상 오르고, 사람 판정 정답이 더 많음, 환각 0
  - 30문항 사람 판정이 2문항 넘게 떨어지지 않음, 환각 0
  - 이어지는 질문 정답이 1턴 넘게 떨어지지 않음, 환각 0
  - 비용·시간은 B-2와 같음
- 계획 1-4는 30문항(27/30)과 이어지는 질문(17/18)을 고정 숫자로 견줬다. 이번에는 같은 실행 안의 비교 대상과 견준다. 허용 폭(2문항, 1턴)은 같다(채팅 Claude 해석, 결정기록 028의 "같은 실행 안 비교").

### 둘을 합쳐 정하는 법 (채팅 Claude 기본값)

- **B를 반영하려면 최종 후보도 A 기준을 운영 그대로와 견줘 모두 통과해야 한다**(A-1·A-2·A-3, 검토 반영). 그래서 최종 후보도 5C 3회를 모두 찾아야 한다. 허용 폭이 겹쳐서(A에서 1, B에서 1) 운영보다 더 많이 떨어지는 일도 막는다.
- A·B 모두 통과: B를 반영한다(B에는 쪽 표시 지우기가 들어 있다).
- A만 통과: 쪽 표시 지우기만 반영한다.
- 둘 다 통과하지 못함: 운영을 그대로 두고 미채택 결정기록을 남긴다.

## 측정 전 결정: 계획 보완 (2026-11-16, 사용자 결정)

도구 출력을 보기 전(0단계 측정 전)에 정했다. 계획서 끝 "계획 보완" 절과 같은 내용.

- ② 쪽 표시를 지운 뒤 제목 위치를 맞춰 주는 `strip_plain_page`를 `ingest/page_marker.py`에 더했다. 지운 구간과 글자 범위가 겹치는 제목은 버리고, 구간 뒤 제목은 지운 길이만큼 당긴다. Task 6 "<도구> 800자"와 Task 8 소제목 실험 조각이 쓴다
- ③ Task 4 Step 6(도구 실행) 뒤, Step 7(판정) 전에 `markdown_to_plain` 출력에 남은 기호를 도구별로 숫자로만 센다(백슬래시 escape, HTML 태그 이름별, 마크다운 링크 `](`, 홑 `*`·`_`로 감싼 글 후보). 0이 아니면 멈추고 보고한다. 정리 규칙은 사용자·채팅 Claude가 정한 뒤 테스트로 고정하고 판정한다
- ④ 제목 적중(heading_hit_rate)의 "포함" 판정을 좁힌다(사용자 결정, Step 7 전·도구 출력 보기 전). 공백을 지운 뒤 한쪽이 다른 쪽에 들어 있고, 짧은 쪽이 2자 이상이며 긴 쪽 길이의 절반 이상일 때만 맞다(같은 쪽 조건은 그대로). 테스트: 목차 "경고"↔제목 "경고" 맞음, 목차 "제품을 설치할 때"↔제목 "설치"·"때" 틀림.
- ⑤ 삼성 38쪽 소수점 검사(decimal_ok)는 "4.0"과 "kg" 사이 공백이 0개 이상이어도 통과한다(사용자 결정, Step 7 전·도구 출력 보기 전). "4 0 kg" 모양 검사는 그대로. 테스트: "4.0kg"·"4.0  kg"·"4.0 kg" 통과.
- ⑥ GPU(사용자 결정, 측정 결과 보기 전): CPU로 먼저 돌리고, CPU에서 설명서 하나에 30분을 넘긴 도구만 같은 설정(같은 백엔드·옵션, 장치만 GPU)으로 RTX 4070에서 다시 돌린다. GPU용 설치도 1시간 제한 안. GPU로 통과한 도구는 "GPU 필요"로 기록하고, 그 도구가 이기면 결정기록에 "적재가 이 컴퓨터 GPU에 의존"을 적는다. 설계 탈락 조건 1은 "이 컴퓨터에서 돌릴 수 있어야 함"으로 읽는다. 코드: Step 7 기본 모드가 run.json의 `gpu_required`를 표에 "GPU 필요"로 보여 주고, 조건 1의 30분 넘음은 마지막으로 돈 장치의 `run_seconds` 기준이다(`excluded`가 true여도 조건 1).
- ⑦ 도구 쪽 글에도 운영과 같은 `clean_text`를 적용한다(사용자 결정, 측정 결과 보기 전). 순서: markdown_to_plain → clean_text → (쪽 표시 지우기). 0단계 판정(조건 2·5·6, 제목 잡기)과 1단계 모두 같은 순서. `--leftover` 셈은 ③ 그대로 markdown_to_plain 결과에 센다. 제목 위치 처리(R22, Claude Code 판단): `ingest/plaintext.py`의 `clean_plain_page`가 줄마다 clean_text를 적용해 결과 text가 `clean_text(pp.text)`와 같고, 지워진 줄의 제목은 버리고 남은 제목은 새 줄 시작 위치로 옮기며 깨끗해진 줄이 제목 글자로 시작하지 않으면 버린다.
- ⑧ 후보에 Unstructured(오픈소스 `unstructured` 라이브러리, `partition_pdf`)를 더하고 다른 도구 뒤 맨 마지막 차례로 돌린다(사용자 결정 2026-11-16, 측정 결과 보기 전). `strategy="hi_res"`로 지정한다(화면 배치 모델로 제목·표를 나누는 것이 넣는 이유라서). 기본값 auto가 아니라는 것을 "바꾼 옵션"으로 기록하고 그 밖의 옵션은 기본값. 제목은 요소 종류 Title, 쪽 번호는 요소의 쪽 정보(실제로 나오는지 먼저 확인하고, 안 나오면 기록한 뒤 한 쪽짜리 PDF로 나눠 돌림). 탈락 조건·설치 1시간·실행 30분·⑥ GPU·⑦ clean_text 순서는 다른 도구와 같다. 라이선스(코드·모델)를 기록한다. 장부 1단계 실험 조각은 최대 7벌(예상 +0.01달러). Claude Code 판단: Unstructured 요소를 마크다운으로 바꾸는 법은 Title 요소는 "# " + 글, 나머지 요소는 글 그대로 한 줄씩(표도 글, HTML 표는 쓰지 않음), 쪽마다 요소 순서대로 잇는다(다른 도구와 같은 markdown_to_plain을 쓰려고).
