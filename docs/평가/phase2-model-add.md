## 판단 기준 (설계 9.3 그대로, 측정 전 확정, 결과를 본 뒤 바꾸지 않음)

1. 지표: **모델 1개를 추가하는 추가 작업 시간(분)**과 **사람이 직접 한 단계 수**.
2. 재는 범위 (사용자 결정 2026-11-20): PDF 파일을 손에 넣은 시점 → 운영 화면에서 그 모델이 보일 때까지에서 **확인 질문 쓰기·판정·배포 대기를 뺀 시간**("추가 작업 시간")으로 비교한다. 전체 시간도 함께 적는다. 사람 단계 수도 같은 범위에서 센다.
   - 이유: 비교용 모델을 다시 넣을 때는 1일차에 쓴 확인 질문을 그대로 써서 질문 쓰기가 0분이 된다. 전체 시간으로 비교하면 도구와 상관없이 빨라 보인다.
3. 기록 방법 (제안): 시간 기록지에 단계마다 시작·끝 시각을 적는다. 쉬는 시간은 "멈춤" 줄로 적고 뺀다. 사람 단계 = 기록지에서 사람이 손이나 판단을 쓴 줄(입력, 고르기, 결과를 읽고 진행을 정함, 명령 실행). 도구나 배포를 기다리기만 한 줄은 세지 않는다. 기록지 양식은 계획 때.
4. 전: 1일차, 비교용 모델을 지금 방식으로.
5. 후: 도구로 ① 비교용 모델을 같은 조건으로 다시, ② 상호 테스트에서 실제로 요청된 모델 최대 2개. ②는 개선 판정에 쓰지 않고 기록만 한다 (판정은 ① 하나의 숫자로).
6. 개선 판정 기준 (사용자 결정 2026-11-17, 재는 범위는 2026-11-20): 비교용 모델 재추가의 **추가 작업 시간이 전의 절반 이하**이고 **사람이 직접 한 단계 수가 줄면** 개선. 둘 중 하나라도 못 맞추면 "개선 확인 못 함"으로 기록한다.
7. 확인 질문 구성 (사용자 결정 2026-11-20): 10개 = 설명서 앞·중간·뒤에서 고르게 고른 사용법·기능·관리 질문 8개 + 설명서나 연결한 해결 가이드에 실제로 있는 에러 코드 질문 2개.
   - 원문에 에러 코드가 없으면 10개를 고르게 뽑는다.
   - 함정 질문(설명서에 없는 내용)은 넣지 않는다.
   - 질문과 정답 쪽(답이 있는 쪽 모두)은 **적재 전에** 쓰고 파일 해시를 커밋한다.
   - 비교용 모델은 전·후에 같은 질문을 쓴다.
8. 합격선 (모델마다, 사용자 결정 2026-11-17): 사람 판정으로 **정답 8개 이상 · 환각 0**.
   - 판정 규칙: `docs/평가/평가-규칙.md` "사람 판정"(결정기록 033 덧붙임 규칙 포함). 비교할 상대 방법이 없어 가린 판정은 하지 않고, v1.9 판정 화면의 원문 보기·검색 기능은 다시 쓴다 (제안).
   - 경계 판정 (사용자 결정 2026-11-20): 경계 판정을 오답·환각 쪽으로 뒤집어도 합격선을 넘을 때만 합격이다. 합격하면 실제 요청자에게 "추가됨" 메일이 가기 때문이다.
   - 미달이면 운영에 열지 않고(8.3) "추가됨"으로 바꾸지 않으며 원인을 기록한다. 질문 세트를 결과에 맞춰 고치지 않는다.
   - 적재 문제(추출·쪽 표시·json·가이드 연결)를 고친 경우에만 같은 질문으로 다시 돌린다 (제안: 1번까지, 계획 때 측정 전에 확정). 실제 요청 모델이 끝내 미달이면 "추가 어려움"(사유 적음)으로 바꾼다 (제안).
9. 결정기록 032 "다시 볼 조건"과의 관계 (제안): 확인 질문에서 "설명서에 없는 코드에 다른 코드의 해결 절차를 붙이는" 환각(032의 267 사례)이 나오면 그 모델은 환각 0을 못 맞춰 불합격이다. 이 답은 032의 근거로 기록만 하고, 쪽 표시 지우기를 다시 정하는 일은 2차 뒤에 한다 (2차는 질문·답변 코드를 바꾸지 않음, 3.4·3.5).
10. 한계로 적을 것: 같은 모델을 두 번째 넣을 때는 손에 익어 빨라지는 효과가 섞인다. 그래서 처음 보는 모델(5의 ②)도 함께 잰다. 표본이 작다.
11. 비교용 모델 후보 (제안): 글자가 있는 PDF + 지금 있는 브랜드(삼성·LG) + **지금 있는 카테고리(세탁기·에어컨)** 제품. 건조기 카테고리를 만드는 시간이 전후 비교에 섞이지 않게 하려는 것이다. 1일차에 정한다.
12. 비교용 모델 재추가 절차: 비교용 모델의 json 항목과 운영 조각 중 그 문서의 행만 되돌린 상태에서 도구로 다시 넣는다. 기존 3개 모델의 조각과 실험 조각(`bundle_chunks`)은 건드리지 않는다. DB 조각 삭제는 사용자 확인 뒤.
