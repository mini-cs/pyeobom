# 평가 규칙

측정·평가·판정 작업을 시작하기 전에 읽는다(CLAUDE.md 작업 규칙). 2026-11-10 정리, 근거는 검색 개선 계획(`docs/superpowers/plans/2026-11-09-search-paraphrase-plan.md`)과 결정기록 028·029.

## 판단 기준

- 판단 기준은 측정·집계 전에 확정해 기록하고, 결과를 본 뒤 바꾸지 않는다.
- 계획에 없는 판정 규칙(분모·반복 횟수·동점 처리 등)이 필요하면 측정·집계 전에 멈추고 사용자에게 묻는다.
- 기록이 늦으면 늦었다는 사실을 남긴다(예: 검색 개선 2단계 집계 전 확정 사항, 계획 Task 7).

## 평가 세트와 실험 방법

- 실험 방법(사전, 생성 질문 등)은 평가 세트를 보기 전에 설명서만 보고 완성한다.
- 평가 세트의 기대 근거는 답이 있는 쪽을 모두 적는다.

## 사람 판정

- 사람 판정은 방법 이름을 가린 판정지로 한다(답 섞기, 무작위 번호, 같은 답 묶기). `python -m measure.stage2 <결과 CSV> --blind`
- 대응표는 git 밖에 두고 SHA-256 해시만 판정 전에 커밋한 뒤, 판정 후 공개한다. 해시는 저장소에 들어가는 내용(LF) 기준이다(CLAUDE.md).

## 이미 코드로 지켜지는 것

- 실행 설정을 결과 옆 `.settings.json`에 남기고, 운영 기본값과 다르면 경고(`evaluation/run_config.py`)
- 봉인된 확인용 세트 거부(`measure/stage2.py`)와 봉인 해시 확인(`tests/evaluation/test_paraphrase_set.py`)
- 받은 조각 번호를 조각 단위로 기록(`retrieved_chunk_ids`)
- 응답 시간은 같은 실행 안에서 비교하고, 규칙으로 막힌 응답은 평균에서 뺀다(`evaluation/scoring.py`, `measure/stage2.py`, 결정기록 028)
- 테스트 중에는 Langfuse 추적을 끈다(`tests/conftest.py`)

## 측정 팁

- 한글 본문을 `curl`·`vercel curl`로 보낼 때는 UTF-8 파일로 보낸다(`--data-binary @파일`). 셸 인자로 넘기면 한글이 깨져 `INVALID_REQUEST`가 난다(2026-11-10 미리보기 확인).
