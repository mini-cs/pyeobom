## Task 6 실험 설계: 바꾸기 시간 줄이기 (실행 전 확정, 2026-11-09)

> 계기: Task 4 미리보기에서 바꾸기 단계 2,311ms(채택 조건 3은 평균 증가 1.5초 이내). 아래 설계와 채택 규칙은 실행 전에 적었고 결과를 본 뒤 바꾸지 않는다.

**대상:** 새 세트(`evaluation/followups.csv`, 확정본)의 2~3번째 질문 **18턴**. 바꾸기 단계만 호출한다(검색·답변 없음).
- 앞 대화는 모든 설정이 같은 것을 쓰도록 **고정**한다: 현재 설정으로 새 세트를 한 번 전체 실행(`--followups --label v15-fu-hist`)한 결과의 가린 질문·답을 history로 쓴다.
- 시간(`rewrite_ms`)은 로컬 PC에서 바꾸기 호출 하나를 잰 값이다(운영 함수는 싱가포르에서 부름, 절대값보다 설정 간 비교용).

**설정 (각 2회 실행, 기준도 같은 18턴으로 다시 잼)**

| 설정 | 모델 | 추론 강도 | 앞 대화 | 바꾸기 | 근거·출처 |
|---|---|---|---|---|---|
| 기준 | `gpt-6-luna` | low | 최근 3개 전체 | 항상(앞 대화가 있으면) | 현재 설정(rewrite_v2, 출력 상한 300) |
| A 빠른 모델 | `gpt-6.1-terra` | low | 최근 3개 전체 | 항상 | OpenAI 모델 목록(2026-11-09 확인)에서 GPT-6 중 유일하게 "A fast, efficient model"로 설명된 모델. 가격 $1/$5 (Luna $0.10/$0.50의 10배). 공식 문서는 Luna와의 속도를 직접 비교하지 않는다 |
| B 추론 강도 낮추기 | `gpt-6-luna` | **none** | 최근 3개 전체 | 항상 | Luna 모델 페이지의 `reasoning.effort` 값 중 가장 낮은 값(결정기록 017) |
| C 앞 대화 줄이기 | `gpt-6-luna` | low | **직전 질문 + 직전 답 앞 200자** | 항상 | 사용자 지정 |
| D 필요할 때만 바꾸기 | `gpt-6-luna` | low | 최근 3개 전체 | **규칙에 맞을 때만** | 아래 규칙. 세트에 맞춰 고르지 않고 일반적인 한국어 이어지는 질문 표지로 정함 |

**D 규칙 (코드로, `measure/compare_rewrite.py`의 `needs_rewrite`)** — 하나라도 맞으면 바꾼다
1. 가리키는 말: 문장 첫머리나 띄어쓰기 뒤의 `그거·그건·그게·그걸·그것·거기·그곳·그때·그런·그렇게·그럼·그러면·그래도·이거·이건·이게·이걸·저거·저건`, 또는 `그·이·저` + 띄어쓰기(예: "그 필터")
2. 생략 끝말: `도요?`·`땐요?`·`때는요?`·`면요?`·`은요?`·`는요?`로 끝남
3. 짧은 질문: 공백을 빼고 10자 이하
- 건너뛴 질문은 원래 질문으로 검색하고, 추가 시간은 0초로 센다.

**재는 것**
- 설정별 `rewrite_ms` 중앙값·최대(바꾸기를 부른 턴), 이어지는 질문 18턴의 **평균 추가 시간**(D의 건너뛴 턴은 0초)
- 바꾸기 정확도(사람 판정 `human_rewrite_ok`): 기준과 같은 문장은 판정을 이어받고, 다른 문장만 새로 판정
- 비용(토큰 × 공식 가격)
- D: 건너뛴 턴 수와 그중 **"바꿔야 하는데 건너뛴 수"**(사람 판정)

**채택 규칙**
1. 정확도가 기준보다 나빠지지 않은 설정만 후보
2. 후보 중 이어지는 질문의 평균 추가 시간이 가장 짧은 것
3. 단독으로 좋은(후보이면서 기준보다 빠른) 설정끼리 조합 하나를 마지막에 한 번 더 잰다(같은 18턴 × 2회)
- 채택 결과와 측정값은 결정기록 023에 기록한다. 코드 변경이면 테스트 먼저 커밋.
