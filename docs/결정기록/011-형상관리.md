# 011. 형상관리: 기능별 폴더 + 기능별 브랜치 + PR

- 날짜: 2026-10-27
- 상태: 확정
- 배경: AI(Claude Code)가 코드를 많이 쓰는 만큼, 무엇을 어떤 순서와 근거로 만들었는지 기록이 남아야 하고 `main`은 항상 배포 가능해야 한다.
- 선택지:
  - A. `main`에 바로 커밋: 빠르지만 기록이 섞이고 배포가 깨질 위험
  - B. 기능 하나 = 브랜치 하나 = PR 하나, merge commit으로 병합
- 결정: B. 서버 코드는 `app/` 아래 기능 폴더(core·input_guard·catalog·retrieval·answer·ask)로 나누고 테스트도 같은 구조를 따른다. 브랜치 이름은 `<type>/<기능>`, `main` 직접 커밋 금지(최초 커밋 제외), 한 번에 브랜치 하나. 코드 작업은 "실패하는 테스트 커밋 → 구현 커밋" 두 번으로 나눠 TDD 순서를 기록에 남기고, Vercel 미리보기에서 확인한 뒤 병합한다. 커밋 메시지는 `<type>(<scope>): 한국어 제목` + 무엇을·왜·테스트.
- 맞바꾼 것: 작은 수정도 브랜치·PR을 거쳐 시간이 더 든다.
- 다시 볼 조건: 팀 작업으로 바뀌면 리뷰 규칙(승인자 수, 보호 브랜치 설정)을 더한다.
- 관련: 기획서 11.5, 구현 계획 "브랜치 전략"
