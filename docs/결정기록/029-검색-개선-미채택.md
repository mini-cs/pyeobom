# 029. 검색 개선(표현이 다른 질문) 미채택, 운영 M0 유지

- 날짜: 2026-11-10
- 상태: 확정 (사용자 결정)
- 관련: 계획 `docs/superpowers/plans/2026-11-09-search-paraphrase-plan.md`(판단 기준 1-4, Task 7), 리포트 `docs/평가/search-improvement.md`, 결정기록 012·015·020·028

계획 Task 8에서는 3단계(확인용 봉인 해제) 뒤에 결론과 무관하게 이 기록을 쓰기로 했으나, 2단계에서 통과한 방법이 없어 3단계 없이 끝났으므로 지금 쓴다.

## 시험한 방법

| 이름 | 방법 | 질문당 추가 비용 |
|---|---|---|
| M0 | 지금 운영 검색(기준) | 0 |
| M1 | 조각 앞에 "모델 · 문서 제목 · 장 이름 · 소제목" 한 줄을 붙여 다시 임베딩 | 0 |
| M2 | 조각마다 사용자가 물을 법한 질문(설명서만 보고 AI 생성, 근거 문장 확인)을 함께 임베딩, 점수 = max(조각, 질문들) | 0 |
| M3 | 용어 사전(설명서 기능 이름 → 평소 표현, 사용자 검토)으로 질문에 설명서 용어를 덧붙임 | 문자열 비교만 |
| 조합 | M1+M2: 점수 = max(M1 제목 붙인 조각, 그 조각의 M2 질문들) | 0 |

평가 세트는 구글 폼으로 모은 표현이 다른 질문(P 세트, 2명 41문장, 카드 단위로 개발용 21·확인용 20)과 1차 30문항이다. 판단 기준은 계획 1-4(2026-11-09 확정, 이후 변경 없음).

## 결정

- **미채택.** 운영 경로(검색·적재·답변)는 바꾸지 않고 M0를 유지한다.
- 기준을 바꾸거나 같은 세트로 다시 고르지 않는다.
- 확인용 P 세트는 열지 않는다(봉인 해시 `ca5b83dd…085e` 그대로).
- 실험 표 `chunk_variants`(Neon production 브랜치)는 남겨 둔다(사용자 결정). 운영 검색은 이 표를 참조하지 않는다(`variant`를 넘기는 실험 경로에서만 사용).

## 한계

- 판정 전에 방법 이름이 붙은 답 목록이 한 번 노출됐다(사용자·채팅 Claude 모두 봄). 이후 가린 판정지로 판정했다.
- 2단계 응답 시간은 같은 실행 안 1회 측정이다.
- 경계 3개(답 208·211·326)는 사용자가 판정 기준 문구에 따라 결정했다.
- 집계 전 확정 사항의 저장소 기록이 집계보다 늦다(커밋 순서로 증명되지 않음).
- 대응표가 판정 전에 있었다는 근거는 파일 시각뿐이다(git 제외 파일이라 커밋 기록 없음). 판정 후 `evaluation/results/stage2-pdev-blind-key-2026-11-10.json`으로 공개했다.
- 분모: 함정은 p16-2 하나이고 p01-1은 함정이 아니다. 함정을 뺀 분모(20)로 세도 M2는 기준에 못 미쳐, 분모 선택이 결론을 가르지 않았다.
- 1단계 적중 증가(M2 +3문장)와 2단계 정답 증가(+1문장)의 차이는 원인을 확인하지 못했다.
- 경계 판정 민감도: 경계 3개를 각각 뒤집는 8가지 경우 M2−M0 차이는 0~+3문장이고, 208(p09-1·M2)을 정답, 326(p19-1·M0)을 오답으로 둘 다 바꾼 1가지 경우에만 +3으로 정답률 기준을 통과한다(하나만 바꾸면 +2로 미달). 결론은 경계 판정 두 개(208·326)에 걸려 있었다. 경계 판정은 방법 이름을 가린 채 미리 정한 판정 기준에 따라 사용자가 결정했으므로 결론은 그대로 둔다. 211(p16-1·M2)은 근거에 없는 이유를 덧붙인 답이라 더 엄격한 규칙이었다면 M2에 불리한 쪽이었다(리포트 "경계 판정 민감도").
