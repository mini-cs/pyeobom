# 023. 질문 바꾸기(방법 A)와 바꾸기 설정

- 날짜: 2026-11-09
- 상태: 확정 (계획 2 Task 8 마감, 2026-11-09. 채택 조건 3은 명시적 예외, 결정기록 028)

## 방법 A를 고른 이유 (설계 5·6절)

- 이어지는 질문("그건 얼마나 걸려요?")을 그대로 검색하면 무엇을 묻는지 몰라 엉뚱한 조각을 찾는다. **질문을 혼자 읽어도 되는 문장으로 바꾼 뒤 1차와 같은 검색·답변·인용 검증을 그대로 쓰면**, 검증된 1차 경로(모델 필터, 진단 안내 규칙, 인용 검증)를 바꾸지 않고 이어지는 질문만 다룰 수 있다.
- 앞 대화가 없으면 바꾸기 단계를 건너뛰어 1차와 똑같이 동작한다(하위 호환, 1차 평가로 회귀 확인 가능).
- **답변 AI에 앞 대화를 넘기지 않는 이유:** 앞의 답을 근거처럼 쓰는 것을 막기 위해서다. 답의 근거는 이번에 검색한 설명서 조각뿐이어야 1차 인용 검증이 의미가 있다.

## 결정 (Task 3·4)

- 앞 대화(`history`)가 있으면 **질문 바꾸기 단계**에서 새 질문을 "혼자 읽어도 되는 한 문장"으로 바꾼 뒤, 1차와 같은 방식으로 검색·답변한다(방법 A).
- **앞 대화는 바꾸기 단계에만 쓰고 답변 AI에는 넘기지 않는다.** 답변 AI에는 바뀐 질문과 설명서 조각만 간다(`test_answer_ai_never_receives_history_text`로 고정).
- 바꾸기 실패(시간 초과·API 오류·형식 오류)는 원래 질문으로 진행한다.
- 프롬프트는 `rewrite_v2`: v1 규칙에 "가리키는 말은 사용자가 앞 질문에서 쓴 말로 바꾼다. 앞 답에만 나온 다른 용어로 바꾸지 않는다." 추가(`docs/프롬프트.md` 변경 기록).

## 바꾸기 설정 (Task 6: 바꾸기 시간 줄이기 실험)

- 계기: Task 4 미리보기에서 바꾸기 단계가 2,311ms. 채택 조건 3은 평균 응답 시간 증가 1.5초 이내다.
- 방법: 확정된 새 세트의 2~3번째 질문 18턴 × 2회, 앞 대화 고정, 설정을 번갈아 호출. 바꾼 문장은 사람이 판정했다. 설계와 채택 규칙은 실행 전에 적었고 결과를 본 뒤 바꾸지 않았다.

| 설정 | 바꾸기 정확도 | 평균 추가 시간(로컬) | 비용(36턴) |
|---|---|---|---|
| 기준(`gpt-6-luna`, 추론 low, 앞 대화 전체, 항상) | 35/36 | 1,936ms | $0.0026 |
| A `gpt-6.1-terra` | 34/36 | 2,355ms | $0.0289 |
| **B 추론 none** | **35/36** | **1,900ms** | $0.0025 |
| C 앞 대화 줄이기(직전 질문 + 답 200자) | 31/36 | 2,128ms | $0.0028 |
| D 필요할 때만 바꾸기 | 31/36 | 1,228ms | $0.0017 |

- **채택: B — 바꾸기 단계만 추론 강도 `none`**(`REWRITE_REASONING_EFFORT`, 기본값 none. 답변은 그대로 low).
  - 채택 규칙: ① 정확도가 기준보다 나빠지지 않은 설정은 B뿐 ② 그중 평균 추가 시간이 가장 짧음 ③ 단독 후보가 하나라 조합 실험 없음.
  - **B의 시간 이득(36ms)은 2회 측정 흔들림 범위라 속도 개선이 아니라, 같은 정확도에서 추론 토큰을 쓰지 않는 설정이다.**
- **D: 가장 빠르지만 생략형 질문(d10-3 "새 걸로 바꾸려면 어디서 사요?")을 놓침 → 2차에서 새 질문으로 판별 방법을 다시 시험한다. 이번 세트에 맞춘 규칙 조정은 하지 않는다.**
- A: 더 느리고 비용이 약 11배이며, 사용자가 말하지 않은 조건("탈수만 할 때")을 덧붙인 문장이 나왔다.
- C: 앞 대화를 줄이면 가리키는 말이 남거나(d10-3·d12-3) 형식 오류가 나서 정확도가 떨어졌다.
- **남은 위험:** B도 평균 추가 시간이 약 1.9초(로컬)로 1.5초를 넘는다. 채택 조건 3은 Task 7에서 Langfuse로 실제 응답 시간 증가를 재서 판정한다.
