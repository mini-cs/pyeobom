# 017. 임베딩·답변 모델 선택

- 날짜: 2026-10-29 (2일차)
- 상태: 확정 (임베딩·답변 모델, 추론 강도 v1 = `low` — 2026-10-29 사용자 확정)
- 배경: 기획서 5장. 전처리(Task 6)의 임베딩 차원(`VECTOR(n)`)과 답변 호출(Task 9)이 모델에 묶이기 때문에, 2일차 첫 작업으로 정한다.
- 확인한 문서 (2026-10-29, OpenAI 공식 개발자 문서):
  - Embeddings 가이드: `text-embedding-3-small`의 임베딩 길이는 기본 **1536**이다(`text-embedding-3-large`는 3072). 최대 입력은 8192토큰이다. `dimensions` 파라미터로 줄일 수 있다.
  - 모델 페이지 `gpt-6-luna`:
    - 가격(100만 토큰당): 입력 $0.10, 캐시 입력 $0.01, 출력 $0.50
    - Chat Completions·Responses 모두 지원한다.
    - 지원 기능에 **Structured outputs**가 있다.
    - `reasoning.effort`는 `none`·`low`·`medium`(기본)·`high`·`xhigh`·`max`다.
    - 문맥 1,050,000토큰, 최대 출력 128,000토큰
  - 모델 페이지 `gpt-6-sol`: 입력 $2, 캐시 입력 $0.20, 출력 $10. Structured outputs를 지원하고, 추론 강도 값은 Luna와 같다.
  - 발표일: OpenAI 발표 글("Introducing GPT-6 Sol and Luna")은 직접 열리지 않았다(403). 여러 보도에서 2026-09-22 발표로 일치했다.

## 결정

| 용도 | 모델 | 설정 (`.env`) | 이유 |
|---|---|---|---|
| 임베딩 (문서 조각·질문) | `text-embedding-3-small` | `OPENAI_EMBED_MODEL=text-embedding-3-small`, `EMBED_DIM=1536` | 한국어 설명서 조각 수백 개 규모라 small로 충분하다. 1536차원이 기본값이라 `dimensions`를 따로 넘기지 않는다 |
| 답변 생성 | `gpt-6-luna` | `OPENAI_CHAT_MODEL=gpt-6-luna` | 출력이 "근거 조각에서 고른 짧은 답 + 인용"이라 큰 모델이 필요하지 않다. 가격이 Sol의 1/20이다 |

- **임베딩 규칙:** 문서 조각과 질문은 **반드시 같은 임베딩 모델**로 만든다. 모델이나 차원을 바꾸면 `chunks`의 임베딩을 **전부 다시 만든다**(`python -m ingest`를 모든 문서에 다시 실행). `ingest/schema.sql`의 `VECTOR(1536)`도 함께 바꿔야 한다.
- **v2 비교 후보:** v1 실패 분석(Task 13)에서 "답변 실패"(근거 조각은 찾았는데 답을 잘못 씀)가 많으면, `gpt-6-sol`을 v2c 비교 실험 후보로 쓴다. 검색 실패가 많으면 모델을 바꾸지 않는다(기획서 6장의 실패 유형별 개선).

## JSON 출력과 추론 강도 (Task 9 구현 기준)

- **JSON 출력:**
  - 모델 페이지에 Structured outputs가 지원 기능으로 있다.
  - Structured Outputs 가이드에는 지원 모델 목록에 `gpt-6-luna`가 따로 적혀 있지 않다("GPT-4o 이후 최신 모델"로만 설명).
  - **Responses API의 `text.format: {type: "json_schema", strict: true, schema: …}`**를 쓰고, Task 9 테스트 호출로 실제 동작을 확인한다.
  - 지원되지 않으면 Task 8의 답변 검증(JSON 파싱·근거 대조)이 막아 준다(계획 Task 9 Step 3).
- **추론 강도:**
  - 기본값은 `medium`이다.
  - 펴봄은 응답 시간을 평가 지표로 공개하고(기획서 6장), 답은 근거 조각 안에서 고르는 일이다. 그래서 **v1은 `low`로 시작한다**(2026-10-29 확정). 설정값 `OPENAI_REASONING_EFFORT`(기본 `low`)로 빼서 코드 수정 없이 바꾼다.
  - 정답률이 낮으면 v2에서 `medium`과 비교한다.
- **Chat Completions 제약:** Chat Completions는 `reasoning_effort`가 `none`일 때만 함수 호출을 지원한다. 펴봄은 함수 호출을 쓰지 않으므로 영향이 없다. 그래도 Responses API를 기준으로 구현한다.
- **확인할 것 (Task 9):** 추론 토큰이 `max_output_tokens`(600) 안에서 쓰이는지 확인한다. 추론에 토큰을 다 쓰고 답이 비어 나오는지, 실제 호출로 확인하기 전까지는 모른다. 비어 나오면 출력 한도를 올리거나 추론 강도를 낮춘다.

## 429 처리 (Task 9, 2026-10-29 확정)

OpenAI Error codes 문서(2026-10-29 확인)의 429 항목은 6개다.

| 429 항목 | `error.code` (문서 표기) | 펴봄 처리 |
|---|---|---|
| Rate limit reached for requests | 문서에 코드 없음 | **1회 재시도** |
| Slow down | `slow_down` (type `rate_limit_error`) | **1회 재시도** |
| Credit balance exhausted | `credit_balance_exhausted` | 재시도 없이 `SERVICE_UNAVAILABLE` |
| Organization spend limit reached | `organization_spend_limit_exceeded` | 재시도 없이 `SERVICE_UNAVAILABLE` |
| Project spend limit reached | `project_spend_limit_exceeded` | 재시도 없이 `SERVICE_UNAVAILABLE` |
| Organization usage limit reached | `organization_usage_limit_exceeded` | 재시도 없이 `SERVICE_UNAVAILABLE` |
| 그 밖의 모르는 코드 | — | 재시도 없이 `SERVICE_UNAVAILABLE` |

- **규칙:** 일반 속도 제한(코드 없음 또는 `slow_down`)만 재시도한다. 문서는 지출·사용 한도와 크레딧 소진에 대해 "재시도해도 복구되지 않는다"고 안내한다. 모르는 코드는 안전하게 재시도하지 않는다.
- **주의:** 일반 속도 제한 429의 실제 `error.code` 값은 문서에 적혀 있지 않다. 실제 응답이 문서에 없는 코드를 달고 오면 "모르는 코드"로 처리되어 재시도하지 않는다. 처음 429를 만나면 코드 값만(키 없이) 서버 로그에 남겨 확인한다.

## 비용 감각 (v1 평가 1회, 추정)

- **임베딩:** 조각 약 330개 × 평균 300토큰 ≈ 10만 토큰이다. 2026-10-29 Embeddings 가이드의 "1달러당 약 62,500쪽(쪽당 약 800토큰)"으로 환산하면 100만 토큰당 약 $0.02다. 그래서 전체 재임베딩도 1센트 미만이다.
- **답변:** 질문 30개 × (입력 약 3,000 + 출력 약 600토큰)이다. 입력 $0.009 + 출력 $0.009로 약 $0.02다. 같은 조건에서 Sol은 약 $0.36이다.
- 추정은 토큰 수 가정에 따른 값이다. 실제 사용량은 Task 12의 OpenAI 사용량 화면으로 확인한다.
