# 043. 2차 구조와 DB 연결 규칙

- 날짜: 2026-11-24
- 상태: 확정 (2차 설계 3판 승인 2026-11-20, 2차 세부 계획 승인 2026-11-21, 덧붙임 승인 2026-11-24)
- 관련: 설계 `docs/superpowers/specs/2026-11-17-phase2-model-request-design.md` 4절·9절, 계획 `docs/superpowers/plans/2026-11-21-phase2-model-request-plan.md` Global Constraints 8·9와 끝 "덧붙임 (2026-11-24)" F-1(이 기록의 번호 039 → 043), 결정기록 005·014, 2026-11-23 개발일지(DB 연결 오류 조사)

## 결정

1. **2차 계정·요청은 Supabase에 둔다.** 로그인은 Supabase Auth(이메일 인증 코드 + 같은 이메일이면 구글), 모델 요청은 Supabase Postgres의 요청 표와 RLS(본인 요청만 보임). 질문·답변(RAG)의 설명서 조각은 지금처럼 Neon에 둔다.
   - **결정기록 005를 바꾼다.** 005는 Neon을 고른 이유 중 하나로 "2차 로그인·기록도 같은 DB"를 들었다. 2차에서는 DB가 둘(설명서 = Neon, 계정·요청 = Supabase)이 된다.
   - 이유(설계 4-4, 사용자 결정): 코드 만료·시도 제한·토큰 확인 같은 보안 코드를 직접 쓰지 않음, 같은 이메일 자동 합치기 제공(공식 문서), 캠프에서 배운 Supabase·RLS를 그대로 씀, RAG 서버를 거의 안 건드림.
   - 감수: DB가 둘이 된다. Supabase 무료 프로젝트는 7일 활동이 적으면 멈추므로 깨우기 예약 호출을 둔다(설계 14-5, 계획 Task 11).
2. **DB 연결 규칙 (사용자 결정 2026-11-21, 계획 Global 8).** 오래 걸리는 작업은 DB 연결을 DB 작업 직전에 열고 바로 닫는다. AI 호출·파일 처리·대기 동안 연결을 쥐고 있지 않는다.
   - 근거(v1.95 DB 연결 오류 조사, 2026-11-23 개발일지): `measure.chunk_context describe`가 트랜잭션을 연 채 연결을 12분 넘게 쥐고 AI를 불러 끝에서 COMMIT 오류가 났다. 서버 `idle_in_transaction_session_timeout`은 5분이다. 재현에서 트랜잭션을 열고 6·16분 놀리면 COMMIT 오류, 1분은 성공. 트랜잭션을 닫고 16분 놀리면 연결이 끊겼다(원인 확인하지 못함).
   - 지금 코드(`describe`, `get_conn()`의 연결 직후 트랜잭션)는 고치지 않는다. 다시 쓸 일이 생길 때 고친다(사용자 결정 2026-11-21).
3. **해결 가이드는 다시 적재하지 않고 연결만 한다 (계획 Global 9).** 새 모델에 가이드를 연결할 때는 `document_models`에 한 줄만 넣는다.
   - 이유: `python -m ingest --doc-id guide-…`는 가이드 조각을 지우고 새로 넣어 조각 번호 298~335가 바뀌고, 평가 세트의 기대 근거가 깨진다. 가이드 연결 판단 기준은 결정기록 014 그대로(모델 단위로 판단, 기능에 묶인 가이드는 그 기능이 있는 모델에만).
4. **알림은 Supabase 데이터베이스 웹훅 → 파이썬 알림 주소(`/api/notify`) → Resend API (설계 4-7).** 새 요청이 오면 운영자에게, 상태가 "추가됨"·"추가 어려움"으로 바뀌면 요청자에게 메일을 보낸다.
   - 이유: Supabase Edge Function(TypeScript)을 쓰지 않아 새 언어를 늘리지 않고, 설명할 수 있는 코드로 둔다. RAG 코드와는 따로인 새 주소만 더한다.
   - 보내는 주소는 `noreply@mail.pyeobom.help`(사용자 결정 2026-11-23, 덧붙임 A-3).

## 바꾸지 않는 것

- 질문·답변 흐름(`app/ask/`·`app/retrieval/`·`app/answer/`)과 적재 설정(임베딩 text-embedding-3-small, `OPENAI_EMBED_DIMENSIONS`·`CHUNK_CONTEXT_MODEL`·`REFINE_MODEL` 비움)은 그대로다(계획 Global 1, 덧붙임 F-3).
