# 004. 기술 구조: HTML + 파이썬 서버 함수(Vercel)

- 날짜: 2026-10-27
- 상태: 확정
- 배경: 5일 안에 화면·서버·AI·배포를 모두 해야 하고, API 키를 화면 코드에 노출하면 안 된다. 개발 직군 발표에서 "구조를 설명할 수 있는가"도 중요하다.
- 선택지:
  - A. Streamlit: 가장 빠르지만 화면 구성 자유도가 낮고, "화면-서버 분리" 구조를 보여 주기 어려움
  - B. Next.js: 화면과 서버를 한 프레임워크로, 하지만 자바스크립트 생태계를 새로 익혀야 하고 전처리·평가는 어차피 파이썬
  - C. HTML/CSS/JS 화면 + Python(FastAPI) 서버 함수를 Vercel에 배포: 화면과 서버가 분리되고, 전처리·평가·서버를 같은 언어로 씀
- 결정: C. 화면은 정적 HTML/CSS/JS, 서버는 FastAPI를 Vercel 함수로 올린다. API 키는 Vercel 환경 변수에만 둔다.
- 맞바꾼 것: 화면 프레임워크의 편의 기능(컴포넌트, 상태 관리)을 쓰지 않는다. 화면이 커지면 코드 정리가 어려워질 수 있다.
- 다시 볼 조건: 2차에서 로그인·기록 화면이 늘어 화면 상태가 복잡해지면 프레임워크 도입을 검토한다.
- 관련: 기획서 5.1, 결정기록 013(Vercel 진입 구조), 018(배포 지역)
