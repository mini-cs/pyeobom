# 028. 채택 조건 3 예외 (v1.5 서버, 이어지는 질문)

- 날짜: 2026-11-09
- 상태: 확정 (사용자 결정)
- 관련: 설계 `docs/superpowers/specs/2026-11-08-chat-redesign-design.md` 7절, 계획 2 Task 7, 측정 `docs/평가/v15-server.md`, 결정기록 023

## 사실

- 채택 조건 3(측정 전 확정): "평균 응답 시간 증가 1.5초 이내 (Langfuse 로컬, 앞 대화 있는 질문 vs 1차 기준값)"
- 운영 설정(TOP_K=5) 재측정: 새 세트 2~3번째 턴(앞 대화 있음) Langfuse `ask` 평균 6,382ms − 1차 기준값 4,873ms = **+1,509ms → 정의대로는 9ms 초과.** 이 값을 그대로 기록한다.
- 같은 실행 안에서 앞 대화 없는 질문과 비교하면 약 **+0.9~1.1초**다(새 세트 1번째 턴 5,259ms 대비 +1,123ms, 30문항 5,450ms 대비 +932ms).
- 같은 날 같은 설정인데도 앞 대화 없는 질문(30문항 평균 5,450ms)이 1차 기준값보다 577ms 느렸다. **원인은 확인하지 못했다.**
- 첫 측정은 로컬 `.env`의 TOP_K=52로 잘못 돌아가 무효로 하고 운영 설정으로 한 번 다시 쟀다. **결과를 본 뒤 기준 아래 값이 나올 때까지 다시 재지 않았다.** 운영 설정 재측정은 이 한 번뿐이다.

- Locust: 운영과 같은 환경(미리보기, 싱가포르)에서 같은 시간대 비교 시 앞 대화가 있으면 중앙값 +1.3초로 1.5초 기준 안. 앞 대화 없는 질문은 1차와 같은 3.3초.

## 결정

- **명시적 예외로 채택한다.** 조건 3의 정의와 측정값은 바꾸지 않고, 예외라는 사실을 이 기록과 리포트에 남긴다.
- 채택 이유
  1. 9ms는 측정 흔들림보다 훨씬 작다(같은 설정의 바꾸기 단계만 2회 쟀을 때도 설정 간 차이가 수십 ms였다, 결정기록 023).
  2. 조건 3의 정의가 **다른 날의 기준값과 비교하는 방식이라 공정하지 않다**는 것을 이번에 발견했다. 앞 대화가 없는 질문도 577ms 느렸고 그 원인은 확인하지 못했다.
  3. 조건 1·2는 통과했다: 30문항 사람 판정 27/30(v2a와 같은 수, 변동 폭 안), 환각 0 / 새 세트 바꾸기 정확도 17/17, 정답률 30/31(이어지는 턴 17/18), 환각 0.

- 근거 관련성 개선은 나타나지 않음(이어지는 턴 0.297). 채택 근거는 조건 1·2 통과와 9ms가 측정 흔들림 범위라는 점이며, 근거 관련성은 채택 조건에 포함되지 않음. 2차 후보(조각 수 줄이기·재순위)와 함께 추적.

## 앞으로

- 시간 조건은 **같은 실행 안에서 앞 대화 없는 질문과 비교**하도록 정의를 고친다(설계 문서 7절, 계획 3부터 적용).
- 평가·측정은 실행 설정을 결과 옆 `.settings.json`에 남기고, 운영 기본값과 다르면 시작할 때 경고한다(TOP_K=52 사고 재발 방지).
