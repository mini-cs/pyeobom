- 날짜: 2026-11-20
- 상태: 확정 (설계 6절 측정 전 기준대로 판정, 응답 시간을 세는 법은 자동 값을 본 뒤·사람 판정 전 사용자 결정 2026-11-20)
- 관련: 설계 `docs/superpowers/specs/2026-11-20-embedding-large-design.md` 6절, 계획 `docs/superpowers/plans/2026-11-20-embedding-large-plan.md`, 리포트 `docs/평가/embedding-large.md`, 결정기록 015·029·031·032·033·035

## 결정

- **임베딩 large(`text-embedding-3-large`, 1536차원) 미채택.** 3단계 B-2 응답 시간 조건("같은 실행 안 응답 시간 증가 0.5초 이하")을 맞추지 못했다. 두 회차 합친 평균 +631ms(1회차 +478, 2회차 +784)
- 운영은 그대로 `text-embedding-3-small`이다. 운영 코드에 들어간 차원 설정(`OPENAI_EMBED_DIMENSIONS`)은 비어 있어 요청이 바뀌지 않는다(Task 1)
- 3단계 통과 파일(`measure/out/emb-large/stage3-pass.json`)은 만들지 않았다. **확인용 세트는 봉인 그대로**(결정기록 031). 4단계(Task 5)와 운영 반영(Task 6)은 하지 않았다
- 명시적 예외는 없다

## 판정 전 결정 (사용자 결정 2026-11-20, 자동 값을 본 뒤·사람 판정 전)

1. 두 회차를 합치는 법은 계획에 없었다. B-2 응답 시간은 "두 회차 합친 평균"으로 센다. 근거는 사용자 결정과 결정기록 029 선례(조합 +639ms 1회로 미통과, 숫자를 본 뒤 만든 반복 측정 규칙은 쓰지 않음)다. 평가 규칙 36행은 "응답 시간은 같은 실행 안에서 비교하고, 규칙으로 막힌 응답은 평균에서 뺀다"이고, 회차를 합치는 법은 정하지 않는다
   - "회차별로 둘 다 만족"으로 읽어도 미충족이다(2회차 +784ms). 통과하는 읽기는 "한 회차라도 만족"뿐이라, 결론은 고른 세는 법에 기대지 않는다
2. 결론은 미채택으로 확정한다(설계 6절 3단계 "통과하지 못하면 미채택")
3. 사람 판정(답 65개)은 기록용이다. 판정 결과로 결론이 바뀌지 않는다
