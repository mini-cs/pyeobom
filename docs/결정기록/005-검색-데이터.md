# 005. 검색 데이터: Neon + pgvector

- 날짜: 2026-10-27
- 상태: 확정
- 배경: 설명서 조각과 임베딩을 저장하고, 선택한 모델의 문서에서만 검색해야 한다. 설명서 원문은 저작권 때문에 공개 저장소에 둘 수 없다.
- 선택지:
  - A. Neon Postgres + pgvector: 벡터·원문·모델 정보를 한 DB에서 SQL로 다룸, 모델 필터가 WHERE 한 줄, 2차 로그인·기록도 같은 DB
  - B. 전용 벡터 DB(예: Pinecone): 대규모에 강하지만 2차에 Postgres를 또 써야 해 DB가 둘로 나뉨
  - C. 로컬 벡터 DB(Chroma, FAISS 등): Vercel 함수에서는 영구 저장이 안 되고, 배포 파일에 넣으면 저작권 문제
  - D. JSON 파일 + 직접 계산: 가장 단순하지만 설명서 텍스트가 공개 저장소에 올라감(Neon이 막힐 때만 쓰는 비상안)
- 결정: A. 1차 규모(설명서 3개 + 가이드 8개, 조각 332개)에서는 성능보다 운영 단순성, 비용, 2차 연결, 저작권 보관이 기준이다.
- 맞바꾼 것: 무료 플랜은 쉬면 잠들어 첫 요청이 느리다(깨어나는 데 약 0.8초, 결정기록 018 측정).
- 다시 볼 조건: 조각 수가 수만 개로 늘어 검색 속도가 지표를 해치면 색인(인덱스)이나 전용 벡터 DB를 검토한다.
- 관련: 기획서 5.5, 5.6
