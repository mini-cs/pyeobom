## 방법: A. 조각 설명 붙이기 (사용자 결정 2026-11-20 "추천대로", 설계 4절)

- AI가 조각마다 "어느 설명서의 어느 부분에서 무슨 기능·문제·상황을 다루는지" 1~2문장을 쓰고, 그 문장을 조각 본문 앞에 붙여(설명 + 줄바꿈 + 본문) `text-embedding-3-small`로 다시 임베딩한다. 저장 본문·화면·답변 AI·인용 검사는 원문 그대로. 코드 이름 `ctx_small`(보고에만), 기록에는 "조각 설명"
- 고른 이유(설계 1·4절 요약)
  - v1.9 3단계 운영 벌의 틀린 답 19개 중 17개는 정답 근거가 검색 결과에 없었다(검색 실패). 답변 쪽을 고쳐서는 많아야 2개라 합격선 +3에 닿지 않는다
  - 설명은 적재할 때 한 번만 쓰므로 질문마다 호출이 늘지 않는다
  - 029 M1(형식이 정해진 제목 한 줄)은 +2였다. 조각이 무엇을 다루는지 문장으로 쓰면 더 오를 수 있다(확인하지 못함). Anthropic "Contextual Retrieval"(2024-09)은 영어 자료에서 상위 20개 검색 실패가 평균 35% 줄었다고 발표했다(우리 한국어 설명서에서는 확인하지 못함)
  - 재정렬(B)은 질문당 비용이 약 5배로 추정되고 새 업체 키가 필요해 다음 후보로 남긴다. 임베딩 large를 시간 기준만 바꿔 다시 재기는 결과에 맞춘 조정이 되어 뺀다

## 원칙 바꿈 (사용자 결정 2026-11-20, 설계 10절 1)

- v1.7·Fable 설계의 "조각에 글을 덧붙이지 않는다"를 **"검색용으로만 붙여도 된다"**로 바꾼다. 화면 인용·답변 AI가 받는 글·인용 검사에는 원문만 쓴다(`chunks.content`·`bundle_chunks.content`는 원문)

## 사용자 결정 (2026-11-20, 설계 10절)

1. 방법: 조각 설명 붙이기(추천대로). 조각에 검색용 설명을 붙여도 된다(위 원칙 바꿈)
2. 응답 시간 기준: 같은 실행에서 같은 문장·같은 회차에 두 벌 모두 `found`가 true인 쌍만 모아 `latency_ms` 차이(후보 − 운영)의 평균이 +500ms 이하, 두 회차 쌍을 합쳐 평균(설계 6절 B-2). 이 세는 법은 v1.7·Fable·v1.9와 다르고 v1.9 관찰을 보고 정한 기준이다. v1.9 임베딩 large는 이 기준으로 다시 판정하지 않는다(036)
3. 설명을 쓰는 AI: OpenAI 모델, 적재 코드에 넣는다(설계 5절 4)
4. 이름: 노션 개발 타임라인 단계 v1.95(설계 5절 1)
5. 일정: 2차(11/25) 전, 운영 반영까지, 밀리면 반영만 2차 뒤로(추천대로)
6. 설계 승인(2026-11-20)
7. 채택되면 운영 반영은 원래대로 11/24에 한다. 그러면 2차 설계(3판)의 "운영 그대로" 전제를 덧붙임으로 고친다(설계 8절 7). 2차 설계가 이미 승인된 것을 확인한 뒤 다시 물어 정함

## 채팅 Claude가 정한 것 (설계 승인으로 확정, 설계 10절)

1. 실험 이름 "조각 설명 붙이기"
2. 숫자·단계·판정 방법은 v1.9와 같고, 여러 회차 숫자는 두 회차를 합쳐 센다(정답은 ⑰, 비용·시간은 두 회차 합친 평균)
3. 설명 쓰는 모델 `gpt-6-luna` 추론 low, 입력은 그 쪽 글 전체와 설명서 이름(가이드는 가이드 글 전체), 1~2문장 150자 이하, 한 번만, 표본 20개 원문 대조
4. 시간 쌍이 10개 미만이면 두 회차 합친 전체 답 평균으로 판정
5. 장부 상한 1달러
6. 운영 반영 때 DB 구조를 바꾸지 않고 설명은 git 밖 파일로
7. 일정·멈춤 규칙(설계 7절, 4는 고침)
8. 설명 모델을 답변 모델과 따로 고정하고 운영 설정 기록(`run_config.PRODUCTION`)에 남김(승인 때 사용자 질문 "GPT 모델에 따라 다를 수도 있나?"로 덧붙임). 설정 `CHUNK_CONTEXT_MODEL`(비면 꺼짐)·`CHUNK_CONTEXT_REASONING_EFFORT`(기본 `low`)
