# 034. Fable 분할 실험 결론: 미채택

- 날짜: 2026-11-20
- 상태: 확정 (설계 6절 측정 전 기준대로 판정, 사용자 확인 2026-11-20)
- 관련: 설계 `docs/superpowers/specs/2026-11-19-fable-split-design.md` 6절, 계획 `docs/superpowers/plans/2026-11-20-fable-split-plan.md`, 리포트 `docs/평가/fable-split.md`, 결정기록 029·031·032·033

## 결정

- **Fable 줄 번호 분할·Fable PDF 분할 미채택.** 둘 다 0단계 탈락 조건은 넘었지만(버린 위치 0%, 삼성 PDF 분할만 2.9%) 1단계 B-1을 통과하지 못했다. 개발용 P 5위 안이 둘 다 7/20으로 운영 8/20보다 1문장 적다(필요한 것은 운영 +3 이상). 30문항 5위 안은 둘 다 21/25(운영 20/25)
- 최종 후보가 없어 3단계(답변까지)와 4단계(확인용 세트)는 하지 않았다. **확인용 세트는 봉인을 유지한다**(결정기록 031)
- **MinerU 800자 탈락.** 기본 `ocr_mode=auto`는 FX25에서 실행 오류였다. 원인을 확인했다: auto가 세 설명서를 ocr로 분류하고, FX25 6쪽 블록의 VLM 출력에 깨진 UTF-8이 나와 실행 전체가 멈춘다. `ocr_mode=txt`(Claude Code가 계획 허용 범위에서 먼저 진행, 사용자가 진행 중 승인)로 세 설명서를 다시 돌렸으나 0단계 탈락 조건 5(삼성 깨진 글자 줄 41 > 기준 6)로 탈락했다. 어느 설정이든 결론은 같다
- **`bundle_chunks`는 지우지 않는다**(사용자 결정 2026-11-20). 지울지는 2차 뒤 다시 정한다. 남은 벌: `strip_800`, `docling_800`, `marker_800`, `docling_sections`, `fable_lines`, `fable_pdf`
- **결정기록 032 다시 세기는 남았다**(설계 7절, 계획 Task 9, 11/24~25). 결정기록 033에 적은 범위 그대로

## 이유

- 판정은 측정 전에 고정한 숫자(설계 6절 B-1)와 측정 전에 커밋한 코드(`b1_pass`·`pick_final`)로 했다. 결과를 본 뒤 기준을 바꾸지 않았다
- v1.7의 규칙 자르기(Docling 소제목, 결정기록 032)에 이어 AI가 정한 자를 위치도 개발용 5위 안을 올리지 못했다. 자르는 위치를 바꾼 세 방법이 같은 문장에서 함께 오르고 함께 내려 수가 거의 움직이지 않았다(리포트 "관찰", 원인은 확인하지 못함)

## 비용

- OpenAI 실제 약 0.0063달러(장부 상한 1달러). Fable은 실제 지출 0, API 환산 약 1.57달러(줄 번호 분할)·약 1.70달러(PDF 분할), 사용자 손 시간 17분

- `bundle_chunks` 정리는 2차 뒤 사용자가 정한다
