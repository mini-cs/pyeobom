## 방법: A. 임베딩 모델 바꾸기 (사용자 결정 2026-11-20, 설계 4절)

- 후보: `text-embedding-3-large`, 결과 길이 `dimensions=1536`, 조각과 질문 모두. 코드 이름 `emb_large`(보고에만), 기록에는 "임베딩 large"
- 고른 이유(설계 4절 요약)
  - 놓친 정답 대부분이 20위 밖이라(개발용 20문장 중 21~100위 8개, 2026-11-20 사전 확인) 조각 수를 늘리는 방법(C)은 닿지 않는다. 임베딩 모델은 20위 밖까지 겨냥한다
  - 질문마다 추가 호출이 없어 기존 비용·시간 기준을 그대로 쓸 수 있고, 1536이라 DB 열을 바꾸지 않으며, 같은 OpenAI 키를 쓴다
  - 재정렬 서비스(B)는 질문당 비용이 지금의 약 5배로 추정되어 기존 B-2(1.5배 이하)를 넘기 어렵고 새 업체 계정이 필요해 다음 후보로 남긴다
  - 공식 다국어 검색 시험 수치는 3072차원 기준이라, 1536으로 줄였을 때와 우리 한국어 문장에서 오를지는 확인하지 못했다

## 사용자 결정 (2026-11-20, 설계 10절)

1. **채택 기준 숫자는 v1.7·Fable과 같다**(설계 6절 공통). B-1 개발용 P 5위 안 운영 +3 이상(분모 20) 그리고 30문항 5위 안 1문항 넘게 안 떨어짐 / B-2 개발용 사람 판정 정답 +3 이상(분모 21)·환각 0·질문당 비용 1.5배 이하·응답 시간 +0.5초 이하·5C 3회 모두 찾음 / B-3 Fable 설계 6절 B-3과 같음
2. **4단계 판정 방법**(설계 6절 4단계): 확인용 세트 답은 사용자가 전부(가린 판정지). 회귀(30문항·이어지는 질문)는 v1.7 회귀처럼 규칙·AI·사람을 섞는다(⑳). ⑳은 사람 판정 원칙의 명시적 예외로 기록하고, 세 AI 요청문에 덧붙임 판정 규칙(033)을 넣는다
3. **운영 반영 때 질문 모델과 조각 모델이 섞이는 시간**(설계 8절 3): DB 구조는 바꾸지 않고 짧게 허용, 상한 15분. 넘으면 되돌린다. 실제 섞인 시간을 기록한다
4. **이름**(설계 5절 1): 실험 "임베딩 모델 바꾸기", 노션 개발 타임라인 단계 "v1.9"

- 앞서 정한 것: 캠프 2차(11/25) 전에 운영 반영까지, 일정이 밀리면 운영 반영만 2차 뒤로(설계 1절)
