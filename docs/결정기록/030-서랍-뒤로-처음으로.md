# 030. 서랍 맨 윗줄에 뒤로·처음으로·닫기 아이콘 버튼

- 날짜: 2026-11-13
- 상태: 확정 (사용자 결정)
- 관련: 설계 `docs/superpowers/specs/2026-11-13-drawer-nav-design.md`, 계획 `docs/superpowers/plans/2026-11-13-drawer-nav-plan.md`, 결정기록 021(다시 볼 조건), `docs/평가/v15-ui.md` 결과(2026-11-13) "다른 가전으로 가는 길"

## 배경

사용자 테스트(계획 3 Task 10)에서 B·D(4명 중 2명)가 홈 버튼이 없다고 했다. 지금 다른 가전으로 가려면 ☰ 안의 "새 대화"나 브라우저 뒤로 가기를 써야 한다. 결정기록 021의 다시 볼 조건(첫 질문까지 가는 길이 번거롭다는 응답)에 해당한다.

## 고려한 방법 (360px 채팅 화면, 폭은 지금 스타일 값으로 계산한 추정)

| 이름 | 방법 | 장점 | 단점 |
|---|---|---|---|
| A | 위쪽 막대 한 줄에 ←·⌂ 추가 | 고칠 양이 가장 적다 | 모델 이름 자리가 약 84px라 "삼성 BESPOKE AI 콤보"(약 145px)가 잘린다 |
| B | A + "새 대화"를 + 아이콘으로 | 이름 자리 약 132~148px | 아슬아슬하다. "새 대화" 글자가 사라진다 |
| C | 막대에 버튼 다섯 개 + 이름을 둘째 줄로 | 모두 보인다 | 막대가 약 32px 높아진다 |
| D | ←·⌂ 모두 서랍 맨 윗줄 | 막대와 모델 이름이 지금 그대로다 | 테스트 때와 막대가 같아 보여 같은 지적이 다시 나올 수 있다. 뒤로가 두 번 누르기(☰ → ←)가 된다 |
| E | ←는 막대, ⌂만 서랍 | 뒤로가 늘 보인다 | 이름이 한 글자쯤 잘릴 수 있다 |

## 결정

**D를 고른다(아이콘만 + ✕).** 채팅 Claude 추천은 E였다. 사용자는 D의 위험(테스트 때와 막대가 같아 보임, 뒤로가 두 번 누르기)을 듣고 D를 골랐다.

1. ☰ "지난 대화" 서랍 맨 윗줄: 왼쪽 [←][⌂], 오른쪽 [✕]. "지난 대화" 제목은 그 아래 줄 → 2026-11-13 변경(사용자 결정): 코드 검토에서 ←가 ☰ 자리와 겹쳐 ✕를 맨 왼쪽으로. 맨 윗줄은 [✕][←][⌂], 셋 다 왼쪽(가전 고르기에서는 [✕][⌂])
2. ← = 한 단계 위: 채팅 → 그 가전의 모델 고르기, 모델 고르기 → 가전 고르기. 가전 고르기에서는 ←를 숨긴다(⌂와 같아서)
3. ⌂ = 첫 화면(소개)
4. ✕ = 서랍 닫기. 지금의 "닫기" 글자 버튼을 바꾼다
5. ←·⌂를 누르면 서랍이 닫히고 그 화면으로 간다
6. 세 버튼 모두 아이콘만 둔다. 화면 읽기용 이름은 "뒤로", "처음으로", "닫기"

## 맞바꾼 것

- 뒤로가 두 번 누르기(☰ → ←)다. 위쪽 막대는 테스트 때와 같다(→ 아래 2026-11-13 변경: 640px 이하에서만 그대로, 넓은 화면은 ☰만 창 왼쪽 끝).
- 위쪽 막대와 모델 이름은 그대로라 이름이 잘리지 않는다.
- 2026-11-13 변경(사용자 결정): 코드 검토에서 ←가 ☰ 자리와 겹쳐 ✕를 맨 왼쪽으로. 처음 배치([←][⌂] … [✕])는 서랍이 열리면 ←가 ☰와 같은 자리(360px에서 4,8)에 와서, 메뉴를 닫으려고 ☰ 자리를 다시 누르면 한 단계 위로 이동했다. ✕를 그 자리에 두어 같은 자리를 다시 누르면 서랍만 닫힌다. 대신 ✕가 오른쪽 끝이 아니라 왼쪽에 있다
- 2026-11-13 변경(사용자 결정): 640px보다 넓은 화면에서는 ☰만 창 왼쪽 끝으로. 서랍 ✕ 자리와 맞추려고. 재검토에서 폭 약 660~930px(위쪽 막대가 가운데 본문 칸에 있을 때)은 서랍을 연 뒤 ☰ 자리를 다시 누르면 ←나 ⌂가 눌리는 것을 찾았다. 대가: 넓은 화면에서 ☰와 모델 이름 사이가 벌어진다(이름은 본문 칸 왼쪽 여백에서 시작). 고려한 다른 안과 고르지 않은 이유:
  - 서랍을 본문 칸에 맞춤: 넓은 화면에서 서랍이 가운데에 떠 보인다
  - 지금 유지(기록에 폭 조건만 적기): 태블릿 폭에서 ☰ 자리에 ←·⌂가 온다
