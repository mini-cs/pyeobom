# 019. v2a: 근거에 없는 에러 코드는 진단 안내 쪽을 덧붙인다

- 날짜: 2026-11-01
- 상태: 확정 (v2a 측정 전 설계 확정)
- 배경: v1 사람 판정에서 진짜 실패는 4개였다(검색 q12·q20, 규칙 q24, 답변 q16, `docs/평가/2026-11-01-v1.md`).
  - q24("에어컨에 CH10이 떴어요")는 "설명서·가이드에 없다"고는 밝혔다. 하지만 설명서의 스마트 진단 쪽(34·49쪽)이 벡터 검색 20위 안에도 없어서 진단 안내가 빠졌다.
  - 프롬프트 v1의 규칙 4("코드가 없으면 조각에 있는 진단 방법을 안내")는 이미 있는데, 진단 쪽 조각이 맥락에 없어서 지킬 수 없었다.
  - 계획의 v2a(에어컨 코드 키워드를 섞는 하이브리드)로는 진짜 실패 중 고쳐질 문항이 없었다. "CH10"은 근거에 0쪽이고, q16은 이미 1위로 검색됐다.

## 결정

- **질문에서 에러 코드 후보를 뽑고, 검색된 조각 어디에도 그 코드가 없으면, 그 모델의 진단 안내 쪽(`diagnostic_refs`) 조각을 맥락에 덧붙인다.** 이미 있는 조각과 겹치면 빼고 붙인다.
- **원칙 (쪽을 확인하기 전에 정함):** "에러 코드를 모를 때 진단하는 방법"이 설명서에 **분명히** 있는 쪽만 지정한다.
- **모델별 지정 (`data/models.json`의 `diagnostic_refs`):**

| 모델 | diagnostic_refs | 근거 |
|---|---|---|
| LG 벽걸이 에어컨 | `manual:34`, `manual:49` | 34쪽 "스마트 진단하기"(리모컨), 49쪽 "고장 진단하기"(LG ThinQ) |
| LG 드럼 | `manual:54` | 54쪽 "고장 진단하기"(LG ThinQ). 39쪽 "스마트 진단"은 54쪽을 가리키는 짧은 안내라 겹쳐서 제외 |
| 삼성 세탁건조기 | 없음 | 설명서에 고장 진단 기능이 없다 |

- **삼성에서 제외한 쪽:**
  - 11쪽 "오프라인 기기 진단"은 스마트싱스의 **네트워크 연결** 진단이다. 고장 진단이 아니다.
  - 70쪽 "목록에 없는 점검 문자가 표시되면 서비스센터에 문의하세요"는 진단 방법이 아니라 문의 안내다. 이 안내는 "찾지 못함" 답의 고객센터 안내와 사실상 같아서, 빼도 사용자가 잃는 것은 없다.
- **함정 질문과 충돌하지 않음을 확인했다.**
  - q18("삼성 세탁기에 IE 에러가 떴어요", 정답은 찾지 못함)은 삼성에 `diagnostic_refs`가 없어 변화가 없다.
  - 삼성에 70쪽을 넣었다면 "IE"가 근거에 없어 70쪽이 덧붙고, found=true로 답해 환각으로 채점됐을 것이다.
  - 나머지 함정 질문(q09·q28·q29·q30)은 코드가 없는 질문이라 영향이 없다.
- **프롬프트는 v1 그대로 둔다.** 규칙 4가 이미 진단 안내를 지시한다. 한 번에 하나만 바꾸는 원칙(계획 Task 14)에 따라 v2a는 검색 맥락만 바꾼다.

## 맞바꾼 것과 다시 볼 조건

- **맞바꾼 것:**
  - 덧붙이는 조각만큼 입력이 길어진다. 에어컨은 최대 몇 개 조각, LG 드럼은 1개다. 코드가 근거에 없는 질문에서만 붙는다.
  - 코드 후보를 잘못 뽑으면(영문 약어를 코드로 오인) 불필요하게 덧붙을 수 있다. 평가 질문 30개에서 뽑히는 코드를 테스트로 고정한다.
- **다시 볼 조건:**
  - 설명서를 바꾸거나 추가할 때(쪽 번호 재확인)
  - 덧붙인 진단 조각 때문에 다른 질문의 답이 흐려지는 사례가 v2a 측정에서 나올 때
