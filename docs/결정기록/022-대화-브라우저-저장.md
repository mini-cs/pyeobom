# 022. 대화는 브라우저에만 저장 (가린 질문만, 버전 1)

- 날짜: 2026-11-08(설계 5절) ~ 2026-11-11(PR #54 병합, 운영 반영)
- 상태: 확정
- 관련: 설계 `docs/superpowers/specs/2026-11-08-chat-redesign-design.md` 5절, 계획 3 Task 3·5·6, 코드 `public/js/store.js`·`history.js`, 결정기록 021·023

## 배경

- v1.5는 이어지는 질문을 지원하고(결정기록 023), 지난 대화를 다시 열 수 있어야 한다.
- 로그인과 서버 쪽 대화 저장은 원래 2차 계획이다. 개인정보를 서버에 쌓지 않는 것이 1차부터의 원칙이다.

## 결정

1. **저장 위치는 브라우저 저장소(localStorage)뿐이다.** 서버에는 대화를 저장하지 않고 로그인도 없다. 키 `pyeobom.conversations`, 형식 `{version: 1, conversations: [...]}`.
2. **가린 질문만 저장한다.** 서버가 돌려준 `question_masked`(전화·이메일·주소를 가린 질문)를 저장하고 화면에도 그것을 보여 준다. 사용자가 친 원래 질문은 저장하지 않는다.
   - 턴마다 6개 항목: `question_masked`, `rewritten_question`, `answer`, `found`, `citations`, `kind`(답·찾지 못함·브랜드 안내)
   - 대화: `id`, `model_id`, `title`(첫 가린 질문 앞 30자), `created_at`, `updated_at`, `turns`. 대화 하나 = 모델 하나
3. **한도:** 대화 20개, 대화당 턴 30개. 넘치면 최근에 쓴 순서로 남기고 오래된 것부터 버린다.
4. **오류 턴은 저장하지 않고 앞 대화에도 넣지 않는다.** 찾지 못함·브랜드 안내 턴은 저장하고 앞 대화에 넣는다(계획 3 기본값 1). 대화는 첫 질문에 오류가 아닌 응답이 왔을 때 만든다(빈 대화는 남지 않음).
5. **서버로 보내는 앞 대화:** 최근 3턴의 가린 질문과 답 본문(`history`). 근거 원문은 보내지 않는다. 서버는 답이 4,000자를 넘으면 거절하고, 가린 뒤 앞 1,000자만 질문 바꾸기에 쓴다(계획 3 Task 1).
6. **잃지 않게 쓰기:**
   - 저장 직전에 다시 읽어, 다른 탭이나 늦게 온 답이 저장한 대화를 덮어쓰지 않는다.
   - 깨진 항목은 그 항목만 버린다(다른 대화는 지키기).
   - 읽기에 실패했거나 다른 버전 데이터가 있으면 쓰지 않는다(덮어쓰면 그 데이터를 잃음).
7. **저장 실패**(시크릿 모드, 공간 부족 등): 화면은 계속 동작하고 "이 대화는 저장되지 않아요"를 한 번 보여 준다.
8. **지우기:** 서랍에서 대화마다 지우기와 전체 삭제(화면 안 확인 단계). 서랍에 "대화는 이 기기에만 저장돼요. 공용 기기라면 다 쓴 뒤 지워 주세요."를 둔다.
9. **버전을 붙인 이유:** 2차에서 서버 저장으로 옮길 때 형식을 알아보고 옮길 수 있게.

## 맞바꾼 것

- 다른 기기나 다른 브라우저에서는 지난 대화를 볼 수 없다.
- 공용 기기에서는 사용자가 직접 지워야 한다(저장 안내 문구로 알림).
- 브라우저 저장소를 지우면 대화도 사라진다.

## 다시 볼 조건

- 로그인과 서버 저장(2차)을 넣을 때 버전 1 형식을 옮기는 방법을 정한다.
- 한도(20개·30턴)는 시작값이다. 사용자 테스트나 실제 사용에서 모자라거나 남으면 조정한다.
