# 012. 서비스명 '펴봄'과 첫 화면 소개 영역(랜딩 A안)

- 날짜: 2026-10-27 (처음 결정, 기획서 4.2) / 2026-10-29 수정 (아래 "수정" 절)
- 상태: 확정 — 소개 영역 동작은 2026-10-29에 수정함
- 배경: 기획서 11.6의 결정기록 목록에는 처음부터 012가 있었지만 파일은 없었다. 동작을 바꾸면서 기획서 4.2의 처음 결정을 옮겨 적고 수정 절을 붙였다.

## 처음 결정 (2026-10-27)

- **서비스명:** "펴봄". 설명서를 대신 펴 봐 준다는 뜻이다.
  - 웹 검색에서 같은 이름의 가전·설명서 서비스는 찾지 못했다. 다만 검색 결과만으로 없다고 단정할 수는 없다(기획서 4.2 "이름 확인").
- **랜딩:** 별도 랜딩 페이지(사용자용·포트폴리오용) 대신 **앱 첫 화면 위에 소개 영역**을 둔다(A안).
  - 들어오자마자 바로 질문할 수 있다.
  - 1차 일정에 부담이 가장 적다.
  - 별도 페이지는 2차 이후 필요하면 만든다.
- **확정 문구:**

| 항목 | 문구 |
|---|---|
| 웹 제목(`<title>`) | 펴봄 — 가전 설명서, 대신 펴 봐 드려요 |
| 소개 제목 | 세탁기·에어컨, 설명서 대신 물어보세요 |
| 소개 부제·`meta description`·`og:description` | 공식 설명서에서 근거를 찾아 페이지와 함께 알려 드려요 |
| 신뢰 포인트 3개 | 공식 설명서 근거 · 근거 페이지 표시 · 모르면 모른다고 해요 |

- **처음 동작:** 검색창이나 예시 질문을 누르면 소개 영역이 약 0.3초 동안 접혔다. 빈칸으로 바깥을 누르면 다시 펼쳤고, 질문을 보낸 뒤에는 접힌 상태를 유지했다.
  - 이유: 휴대폰 키보드가 올라와 검색창을 가리지 않게 하려는 것이었다.

## 수정 (2026-10-29): 검색창 포커스 시 접힘 → 첫 질문 전송 시 한 줄 머리말

- **발견:** 사용자가 실기기에서 확인해 보니 소개 영역이 짧아서, 검색창을 눌러도 접히는지 애매했다. 폭 360px에서 소개 영역은 약 230px다.
- **바꾼 동작:**
  1. 검색창을 누르거나 떼는 것만으로는 소개 영역이 바뀌지 않는다.
  2. 질문을 실제로 `/api/ask`에 보낼 때 소개 영역(제목·부제·신뢰 포인트)을 접는다. 빈 질문·글자 수 초과처럼 화면 검사에서 막힌 경우는 제외한다. 이때 맨 위 머리말은 **"펴봄 — 가전 설명서, 대신 펴 봐 드려요" 한 줄**이 된다.
  3. 한 번 바뀐 뒤에는 계속 한 줄로 둔다. 새로고침하면 처음 상태로 돌아간다.
  4. 바뀔 때 300ms 전환 애니메이션을 쓴다. "동작 줄이기" 설정이면 애니메이션 없이 바로 바꾼다.
  5. **포커스는 옮기지 않는다.** 검색창 입력이나 답변 읽기를 방해하지 않게 하기 위해서다.
- **이유:** 바꾸는 목적은 "질문 뒤 답변을 화면 위쪽에 보이게" 하는 것이다. 그래서 눈에 띄지 않는 포커스 시점이 아니라 실제 전송 시점에 한 번만 바꾼다. 다시 펼치는 동작이 없으니 화면이 덜 흔들린다.
- **확인 (Playwright, 로컬 + 실제 API):**

| 화면 | 처음 | 검색창 누름 | 뗌 | 빈 질문 전송 | 질문 전송 후 |
|---|---|---|---|---|---|
| 360×640 | 소개 227px | 227px | 227px | 227px (막힘) | **0px**, 머리말 한 줄(53px), 포커스 검색창 그대로 |
| 390×844 | 소개 227px | 227px | 227px | 227px (막힘) | **0px**, 머리말 한 줄(53px), 포커스 검색창 그대로 |

  - 동작 줄이기를 흉내 내면 전환 시간이 0.3s에서 0s가 됐다.
  - 캡처: `docs/design/screens/07-compact-360x640.png`, `07-compact-390x844.png`
- **맞바꾼 것:** 첫 질문 전에는 키보드가 올라온 상태에서도 소개 영역이 화면을 차지한다. 소개가 짧아 감수한다.
- **확인 필요:** 실기기에서 전송 순간 화면이 튀지 않는지(사용자 확인)
