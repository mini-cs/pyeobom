# 012. 서비스명 '펴봄'과 첫 화면 소개 영역(랜딩 A안)

- 날짜: 2026-10-27 (수정 메모 2026-10-29)
- 상태: 확정
- 배경: 서비스 이름과, 처음 온 사람에게 무엇을 하는 서비스인지 알려 줄 방법이 필요했다. 1차 일정에 별도 페이지를 만들 여유는 적다.
- 선택지:
  - A. 앱 첫 화면 위에 소개 영역: 들어오자마자 질문 가능, 일정 부담이 가장 적음
  - B. 사용자용 별도 랜딩페이지: 설명은 풍부하지만 한 번 더 눌러야 질문
  - C. 포트폴리오용 별도 페이지: 채용 담당자에게는 좋지만 1차 사용자에게는 불필요
- 결정: 이름은 "설명서를 펴 보다"에서 온 **펴봄**. 랜딩은 A. 웹 제목 "펴봄 — 가전 설명서, 대신 펴 봐 드려요", 소개 제목·부제·신뢰 포인트 3개(공식 설명서 근거 · 근거 페이지 표시 · 모르면 모른다고 해요). 검색창이나 예시 질문을 누르면 소개 영역이 약 0.3초 동안 접히고, "동작 줄이기" 설정이면 애니메이션 없이 접는다. 포트폴리오 소개는 발표 자료·README·노션으로 대신한다.
- 맞바꾼 것: 소개를 읽기 전에 검색창을 누르면 신뢰 포인트를 못 볼 수 있다.
- 수정 메모 (2026-10-29): 실기기에서 확인해 보니 접힘은 동작하지만 소개 영역이 작아 변화가 잘 보이지 않았다. "첫 질문을 보내면 한 줄 머리말로 바꾸기" 안을 검토했지만, 기능에 문제가 없어 지금 방식을 유지하고 3일차 사용자 테스트에서 "접힘을 알아채는지, 답을 보려고 화면을 내려야 하는지"를 관찰하기로 했다.
- 다시 볼 조건: 사용자 테스트에서 답변을 보려고 화면을 내려야 했다는 응답이 나오면 "첫 질문 후 한 줄 머리말" 안으로 바꾼다.
- 관련: 기획서 4.2
