# 018. 배포 지역: Vercel 함수 sin1 + Neon 싱가포르

- 날짜: 2026-10-29 (2일차)
- 상태: 확정 (운영 배포에서 측정 확인)
- 배경: 계획 Global Constraints의 "Vercel 함수 지역과 Neon DB 지역을 맞춘다"(Task 12)를 앞당겨 처리했다.
  - Task 10 미리보기에서 `/api/ask`의 DB 연결이 약 4초였다. 함수는 Vercel 기본 지역 `iad1`(워싱턴)이었고 Neon은 `ap-southeast-1`(싱가포르)이었다.
  - Neon 지역은 접속 주소의 호스트 이름에서 지역 부분만 읽어 확인했다(주소 전체는 출력하지 않음).
- 확인한 문서:
  - Vercel Functions Limits(2026-08-24 갱신): 함수는 기본으로 한 지역(`iad1`)에서 돌고, 기본 지역은 바꿀 수 있다.
  - Neon Scale to zero(2026-10-29 확인): 무료·유료 모두 5분 동안 요청이 없으면 잠들고, 다음 요청 때 "수백 ms 안에" 깨어난다.

## 결정

- **Vercel 함수 지역을 `sin1`(싱가포르)로 옮긴다.** Neon(`ap-southeast-1`)은 그대로 둔다.
  - 사용자가 대시보드에서 바꿨다.
  - 운영 배포에서 확인한 것: `vercel inspect` → `λ fastapi (20.78MB) [sin1]`, 응답 헤더 `X-Vercel-Id: icn1::sin1::…`(서울 엣지 → 싱가포르 함수)
- **이유:** 질문 1개에 함수와 DB가 여러 번 주고받는다(연결 + 검색). 그래서 함수-DB 왕복을 가장 짧게 하는 것이 효과가 크다. 사용자(한국)와 함수 사이도 워싱턴보다 싱가포르가 가깝다.
- **Neon을 미국으로 옮기지 않은 이유:** 이미 적재한 조각 332개를 새 프로젝트로 다시 넣어야 한다. 사용자(한국)와도 멀어진다.

### 읽은 것

- **DB 연결은 약 4,000 → 36~52ms, 검색은 약 900 → 9~19ms로 줄었다**(이어지는 요청 기준).
- **이어지는 요청의 전체 시간은 약 2~3.5초이고, 대부분이 AI 호출이다(1.4~3.5초).**
- **첫 요청(쉬었다가 다시 쓸 때)은 사용자까지 약 7.7초다.**
  - 함수 안에서 잰 시간(5.3초)과 사용자까지 걸린 시간의 차이 약 2.4초는 Vercel 함수가 새로 뜨는 시간으로 보인다. 직접 나눠 재지는 않았다.
  - Neon이 깨어나는 것을 포함한 DB 연결은 837ms였다. 문서의 "수백 ms"와 맞는다.
- **1차 측정의 q13 #1·#3도 느렸다(DB 연결 약 700ms, 임베딩 약 1.1초).** 새 배포 직후라 Neon보다 함수 인스턴스가 새로 떠서 외부 연결을 처음 맺은 효과로 보인다(추정).
- **한계:**
  - iad1은 미리보기에서 질문마다 1회만 쟀다. sin1은 운영에서 6회씩 쟀다. 환경과 횟수가 다르다.
  - 모두 한국에서 보낸 요청이다.

## 맞바꾼 것과 다시 볼 조건

- **맞바꾼 것:**
  - 함수와 OpenAI API 사이의 거리. OpenAI 서버 위치는 공개 문서로 확인하지 못했다.
  - AI 호출 시간은 iad1 2.9초(1회)와 sin1 1.4~3.5초가 겹쳐서, 이 측정으로는 유불리를 말할 수 없다. 임베딩도 마찬가지다.
- **설정 위치:** 지역은 대시보드에서 바꿨다. 결정기록 013의 원칙(설정을 저장소에 둔다)대로라면 `vercel.json`의 `regions`에 `["sin1"]`을 넣는 편이 다시 만들 때 안전하다. Task 12에서 공식 문서로 확인한 뒤 넣는다.
- **다시 볼 조건:**
  - 사용자가 한국 밖에 많아질 때
  - Neon 지역을 바꿀 때
  - 첫 요청 지연(약 7.7초)이 평가·시연에서 문제가 될 때. 시연 전에 한 번 호출해 깨워 두는 것으로 먼저 대응한다.
