# 001. 주제 변경: 개발자 도구 → 비개발자 반복 업무 → 가전 설명서 Q&A

- 날짜: 2026-10-27
- 상태: 확정
- 배경: 처음에는 개발 직군 평가(정확도·응답 시간·오류율)에 맞추려고 "정답이 있는 일"을 하는 개발자 도구(에러 로그 해석기, 커밋 메시지 분류기 등)를 후보로 봤다. 그런데 "거의 모든 사람이 바이브 코딩을 하는데 이게 사업이 되나?"라는 질문에서 다시 보니, 개발자 도구는 대형 도구(예: 편집기의 커밋 메시지 생성 기능)가 이미 흡수했고 사용자가 직접 만들 수 있어 돈을 낼 이유가 약했다. AI API에 프롬프트만 감싼 "얇은 래퍼"라는 문제도 있었다.
- 선택지:
  - A. 개발자 도구 유지: 평가 지표를 세우기 쉽지만 사업성과 차별점이 약함
  - B. 비개발자 반복 업무 도구(채용공고 분석기, 견적서 비교기, 고지서 해석기 등): 사용자가 직접 만들기 어렵지만 주제마다 근거 데이터 확보가 제각각
  - C. 가전 설명서 Q&A: 문서를 근거로 답하는 구조(RAG)라 동작 설명거리가 많고, 근거가 없으면 "모른다"고 답하는 것이 곧 안정성 시연이 됨
- 결정: C. 기준을 ① 사용자가 비개발자 ② 쓸수록 쌓이는 데이터 ③ 정확도를 숫자로 증명할 수 있고 업무 흐름에 붙어 있음, 세 가지로 다시 세우고 가전 설명서 Q&A를 골랐다.
- 맞바꾼 것: 개발자 도구보다 데이터 준비(공식 설명서 확보, 약관 확인, 글자 추출)가 훨씬 무겁다.
- 다시 볼 조건: 공식 설명서를 근거로 쓸 수 없게 되면(약관·허락 문제, 글자 추출 실패) 가상 설명서(Plan B)나 다른 주제를 검토한다.
- 관련: 기획서 1장
