# 027. 다른 브랜드 질문은 코드로 "찾지 못함" (결정 A)

- 날짜: 2026-11-09
- 상태: 확정 (계획 2 Task 1, PR #30 운영 반영)
- 관련: 계획 `docs/superpowers/plans/2026-11-09-v15-server-followup.md` Task 1, 기준값 `docs/평가/baseline-v1.md`(Promptfoo IE 사례), 결정기록 019, 측정 `docs/평가/v15-server.md`

## 배경

- 1차 Promptfoo 고정 사례에서 삼성 모델에 "LG 세탁기 IE 에러는 무슨 뜻이에요?"를 물으면 `found: true`로 답했다(삼성 70쪽 점검 안내 인용). 같은 종류의 질문 q18은 평가 6회 모두 `found=false`였다. 뚫린 것은 아니지만 1차 기대 동작과 달랐다.

## 결정

- **질문에 고른 모델과 다른 제조사 이름이 있으면 AI를 부르지 않고 `found: false`로 답한다**: "지금 고른 모델은 ○○ 제품이에요. 다른 제조사 제품은 모델을 바꿔서 물어봐 주세요."(`app/core/brand_guard.py`)
  - 위치: 개인정보 가리기 다음, 검색 전. 질문 바꾸기 결과에도 다시 적용한다(결정기록 023).
  - 별칭: 삼성·samsung, 엘지·LG(영문은 대소문자 무시, 앞뒤가 영문자가 아닐 때만).
  - **한글 이름은 허용 목록(2026-11-09, 최종 검토 반영):** 뒤에 띄어쓰기·문장부호·문장 끝, 조사(은·는·이·가·의·을·를·도·랑·이랑·에서), "전자", "꺼"·"거", "세탁기"·"에어컨"·"건조기"·"제품"이 올 때만 브랜드로 본다. 지명(삼성동·삼성역·삼성로·삼성병원)을 브랜드로 잡으면 정상 질문이 막히고, 브랜드를 놓치면 1차처럼 AI가 처리할 뿐이라 놓치는 쪽이 안전하다. 수정 후 1차 30문항 회귀에서 브랜드 안내 0개.
  - 오탐 방지: 1차 평가 30문항과 화면 예시 질문이 모두 규칙에 걸리지 않음을 테스트로 고정했다.
- **이유:** 다른 제조사 정보는 고른 모델의 설명서에 없고, 다른 브랜드의 에러 코드에 이 모델 설명서의 점검 안내를 붙이면 맞지 않는 안내가 될 수 있다. 프롬프트에 맡기면 답이 실행마다 흔들리므로(1차 Promptfoo IE 사례) 코드로 고정한다.

## 규칙 밖: 같은 브랜드 질문(q18)

- q18("삼성 세탁기에 IE 에러가 떴어요", 삼성 모델)은 질문에 고른 모델과 **같은** 브랜드만 있어 이 규칙이 관여하지 않는다.
- 계획 2 Task 7 측정에서 q18이 `found: true`("IE 코드는 이 모델의 설명서에 없다… 서비스센터 문의")로 답한 실행이 있었다. 지어낸 내용이 없어 환각이 아니라 오답(결정 A 기대와 다름)으로 분류했다.
- **결정 A의 빈틈:** 브랜드 이름만 막고, 브랜드 이름 없이 다른 브랜드의 에러 코드를 묻는 질문은 막지 못한다. → 2026-11-10 메움(아래 "빈틈 메우기")

## 2차에서 다시 볼 조건

- 브랜드별 에러 코드 목록 규칙(계획 2 마무리 후 별도 작업): 고른 모델의 설명서·가이드에 없는 코드가 다른 브랜드의 코드 목록에 있으면 같은 안내로 답한다. → 2026-11-10 반영(아래 "빈틈 메우기")
- 모델이 늘어 브랜드가 추가되면 별칭 표(`ALIASES`)와 오탐 테스트를 함께 넓힌다.
- 모델이 늘면 에러 코드 목록(`data/error_codes.json`)도 새 문서에서 다시 뽑고, 출처 대조 통합 테스트로 확인한다.

## 빈틈 메우기: 다른 브랜드 에러 코드 (2026-11-10, 사용자 결정)

- **규칙:** 질문 속 코드가 **다른 브랜드 목록에만 있고 고른 모델 브랜드 목록에는 없을 때만** AI를 부르지 않고 `found: false`로 답한다: "이 코드는 지금 고른 ○○ 모델 설명서에 없는 코드예요. 다른 제조사 제품이라면 모델을 바꿔 물어봐 주세요."(`app/core/brand_guard.py`의 `other_brand_code`·`guard_message`)
  - 막지 않는 경우: 두 브랜드 목록에 모두 있는 코드(LE·FE), 같은 브랜드의 다른 제품 코드(LG 세탁기에서 CH05), 어느 목록에도 없는 코드(q24 CH10).
  - 위치: 브랜드 이름 규칙과 같은 자리(개인정보 가리기 다음, 검색 전)이며 바꾼 질문에도 다시 적용한다. 이름 규칙이 먼저다.
  - "고른 모델 쪽 목록"은 고른 모델과 **같은 브랜드의 모든 문서**에서 뽑은 목록으로 정했다. 그래서 같은 브랜드의 다른 제품 코드는 막지 않는다.
- **코드 목록:** `data/error_codes.json`(코드와 출처만, 설명서 본문 없음). 삼성 14개, LG 46개.
  - 뽑은 방법: DB의 설명서·에러 가이드 조각에서 코드 모양 후보를 정규식으로 뽑았다. 그다음 앞뒤 문맥을 보고 실제 표시 코드만 남겼다. 단위(16A·5CM), 영문 약어(Wi-Fi·LED), 그림 기호(A·B·C), 글자가 깨진 쪽(삼성 79·80쪽)은 뺐다.
  - LG 에어컨 가이드는 "CH05, 53, E0…"처럼 CH를 빼고 숫자만 적은 코드가 있어 CH 코드로 넣었다(CH53 등).
  - 통합 테스트(`tests/retrieval/test_error_codes_source.py`)가 코드마다 출처 문서·쪽에 실제로 있는지, 그 문서가 그 브랜드 모델의 문서인지 DB에서 확인한다.
- **코드 찾기:** 진단 안내(결정기록 019)와 같은 `extract_code_tokens`를 쓴다. 대소문자를 무시하고("tE"→TE) 영단어 안의 글자는 코드로 보지 않는다(IEEE·OEM·TEST). 글자만인 코드(IE·PE)는 질문에 에러 맥락(에러·코드·떴·표시 등)이 있을 때만 코드로 본다.
- **남은 위험:** 글자만인 코드가 에러 맥락과 함께 다른 뜻으로 쓰이면 막힐 수 있다(예: 삼성 모델에서 "옷에 PE 소재라고 표시돼 있어요"). 막혀도 다른 제조사 안내가 나갈 뿐 틀린 정보를 주지는 않는다.
- **오탐 확인:** 1차 30문항 중 막히는 문항은 q18 하나이고, 화면 예시 질문은 하나도 막히지 않는다. 둘 다 테스트로 고정했다.
