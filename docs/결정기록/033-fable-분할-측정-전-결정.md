## 덧붙임 판정 규칙 (설계 5-6, 사용자 결정 2026-11-19)

1. 일반적인 안전 주의(전원 끄기, 전원 플러그 뽑기 등)와 서비스센터 문의 권유는 원문에 없어도 환각이 아니다. 핵심 답이 원문과 맞으면 정답이 될 수 있고, 판정지에 "덧붙임"으로 표시한다.
2. 그 상황에만 해당하는 해결 절차, 숫자, 버튼·기능·코스 이름, 에러 코드 뜻이 원문(그 모델의 설명서·해결 가이드)에 없으면 환각이다.
3. 기존 규칙(질문이 직접 묻는 내용이면 원문과 다른 이유는 오답 등)은 그대로다.
4. 판단이 갈리면 경계 판정으로 표시하고, 뒤집었을 때 결론이 바뀌는지 적는다(기존 규칙).
5. 이번 실험 3·4단계부터 쓴다. v1.7 판정을 다시 세는 일은 아래 "032 다시 볼 조건".

- `docs/평가/평가-규칙.md` "사람 판정"에 1~4를 덧붙였다(2026-11-20).

## 두 방법 이름과 탈락 조건 (설계 머리말·5-2의 4·5-3의 4)

- 이름(사용자 결정 2026-11-20): **Fable 줄 번호 분할**(대화의 "갑": 쪽·줄 번호를 붙인 글을 주고 자를 줄만 받음), **Fable PDF 분할**(대화의 "을": 원본 PDF를 주고 쪽 번호와 그 자리 첫 글자를 받아 코드가 찾음). 실험 조각 코드 이름(`fable_lines`·`fable_pdf`·`mineru_800`)은 보고에만 쓴다.
- Fable 줄 번호 분할 탈락(사용자 결정 2026-11-20, 5-2의 4): 설명서 하나라도 받은 위치 중 버린 것(없는 쪽·줄, 형식이 어긋난 항목)이 10%를 넘으면 탈락. 버린 위치는 쓰지 않고 수를 기록한다.
- Fable PDF 분할 탈락(채팅 Claude 기본값, 사용자 승인, 5-3의 4): 설명서 하나라도 못 찾은 자리가 받은 자리의 10%를 넘으면 탈락. 형식이 어긋나 버린 항목도 못 찾은 것으로 센다.
- 찾는 규칙(5-3의 3)과 Fable 답을 읽는 코드는 Fable 답을 받기 전에 설명서 글만으로 만들고 고정한다. 답을 본 뒤 고쳐야 한다고 보이면 멈추고, 고치기 전 숫자를 남긴 채 사용자가 명시적 예외로 정할지 결정한다.

## Fable 채팅 조건 (사용자 결정 2026-11-20, 측정 전 고정, 설계 5-1 덧붙임)

- 추론 강도 "높음", 메모리 끔, 웹 검색 끔, 프로젝트 밖 새 채팅. 6번(설명서 3개 × 두 방법) 모두 같은 조건으로 돌린다.
- 대화마다 추론 강도(화면 이름 그대로), 메모리, 웹 검색, 채팅 종류(화면에 보인 그대로)를 기록한다. 하나라도 조건이 다르면 멈추고 보고한다(계획 Task 4 Step 4 덧붙임).

## 확인용 기대 근거의 옛 조각 번호 (설계 6절 4단계, 사용자 결정 2026-11-20)

- 확인용 기대 근거에 설명서 옛 조각 번호(`chunk:<1~297>`)가 있으면, 운영과 후보 **모두** 그 옛 조각의 쪽(백업 `measure/out/v17-rollout-backup/`에서 찾음)으로 바꿔 쪽 기준으로 센다. 같은 잣대로 재기 위해서다.
- 조각 번호보다 느슨하다(그 쪽의 어느 조각이 5위 안에 들어도 적중). 해당 문장 수를 리포트에 적는다.
- 가이드 조각 번호는 모든 벌에서 같으므로 그대로 센다.
- 인수인계 노트의 "옛 번호는 새 번호에 맞춘다" 규칙은 운영에만 통하므로 이번 실험에서는 이 규칙을 쓴다(설계 3절).

## 결정기록 032 "다시 볼 조건" (설계 7절)

- 덧붙임 규칙을 정해서 032의 조건("환각 기준을 판정 규칙으로 정리하면 그 규칙으로 회귀 판정을 다시 센다")이 켜졌다.
- **사용자 결정 2026-11-19: Fable 실험 바로 뒤(11/24~25)에 한다.** 그때까지 상태는 "켜짐, 미룸"이다.
- Fable 실험에는 영향이 없다. 운영과 후보를 한 실행 안에서 같은 규칙으로 견주기 때문이다.
- 마감 규칙("미완료", 설계 5-5)은 이 다시 세기에 걸지 않는다(채팅 Claude 기본값, 검토 반영).
- **다시 셀 범위** (Fable 1단계 측정 전에 확정, 채팅 Claude 기본값)
  1. 대상 실행: v1.7 A-3에 쓴 실행 전부(3단계 개발용 21문장 2벌×2회, 회귀 30문항·이어지는 질문 2벌×2회)와 운영 반영 9단계 30문항 2회
  2. 대상 답: 그 실행에서 정답 또는 정답(경계)으로 판정된 답 전부
  3. 채팅 Claude가 그 모델의 설명서·해결 가이드 전체 글자 검색으로 "원문에 없는 절차·숫자·이름"이 있는 답을 골라 사용자에게 보낸다. 이미 짚었던 315·330·267·354를 포함한다. 고른 기준과 고른 수를 함께 적는다.
  4. 사용자가 덧붙임 규칙으로 판정한다.
  5. 다시 센 결과로 A-3을 다시 본다. A-3이 실패로 바뀌면 쪽 표시 지우기를 어떻게 할지 사용자가 정한다(되돌릴 때 쓸 백업: `measure/out/v17-rollout-backup/`).
- 한계: v1.7 대응표는 이미 공개되어 가린 판정이 아니다. 채팅 Claude가 판정 자료(git 밖)를 읽으려면 사용자 승인이 필요하다.
