## 2. 색 (토큰)

방향은 "흑백"이다. 흰 바탕에 검정과 회색만 쓰고 포인트 색은 없다. 제조사 고유 색(LG 빨강, 삼성 파랑)은 쓰지 않는다. 1차의 청록과 미색은 지운다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--color-bg` | `#FFFFFF` | 페이지 바탕 |
| `--color-surface` | `#F2F2F2` | 면 회색: 입력창·내 질문 말풍선·카테고리 타일·추천 카드·근거 박스·안내 |
| `--color-text` | `#111111` | 본문·제목 |
| `--color-text-muted` | `#6B6B6B` | 보조 글자·입력창 안내 문구·남은 글자 수·하단 고지 |
| `--color-border` | `#DADADA` | 구분선·카드 테두리(장식용, 글자 아님) |
| `--color-action` | `#111111` | 검은 알약 버튼 바탕, 보내기 동그라미, 선택 표시 |

- 안내(개인정보 안내, 공용 가이드 경고)는 색 토큰을 따로 두지 않는다. `--color-surface` 바탕에 `--color-text` 글자, 앞에 아이콘과 굵은 라벨을 둔다(결정기록 024).
- 1차에서 지운 것: `--color-primary`, `--color-primary-hover`, `--color-on-primary`, `--color-evidence-bg`, `--color-warning-bg`, `--color-warning-text`.
- 1차에서는 어두운 화면(다크 모드)을 지원하지 않는다.

- **글자 쌍은 모두 4.5:1 이상**이다. 설계·시안의 `#7A7A7A`(흰 바탕 4.29:1, 회색 면 3.83:1)는 미달이라 `#6B6B6B`로 바꿨다(사용자 결정 12).
- **오류 색:** 후보 A(1차 빨강)를 쓴다. 후보 A의 오류 글자는 오류 바탕·흰 바탕·면 회색 어디서나 4.5:1을 넘는다. 오류만은 회색과 확실히 달라야 해서 색 하나를 남긴다.
- **개인정보 안내·공용 가이드 경고:** 후보 B(흑백)를 쓴다. 1차의 갈색·노란 바탕(후보 A)도 통과하지만 포인트 색이 하나 늘어난다. 이 안내는 오류가 아니라 알림이므로 회색 면과 본문색으로 충분하다.
- **면 회색(`#F2F2F2`)과 `#DADADA` 테두리는 흰 바탕과의 대비가 1.12:1, 1.40:1이라 글자가 아닌 요소의 3:1에 못 미친다.** 면 색은 경계를 알아보게 하는 근거로 치지 않는다. 구성 요소마다 아래 단서로 알아본다.
  - 입력창: 안내 문구(4.76:1), 검은 보내기 버튼(18.88:1), 포커스 링(`--focus-ring`). 경계 처리는 아래 "사용자 결정 대기"다.
  - 카테고리 타일·추천 카드: 아이콘 + 글자(본문색 16.87:1 또는 보조 글자 4.76:1).
  - 근거 박스: 출처 라벨과 인용 글자(본문색).
- **입력창 경계: 사용자 결정 2026-11-10, A안(면 `#F2F2F2`만, 테두리 없음). 이유를 남긴 명시적 예외다.**
  - 사실: 면 `#F2F2F2`는 흰 바탕과 1.12:1이다. W3C 이해 문서(https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html, 2026-11-10 확인)의 Figure 34는 "Text inputs that have no border and are differentiated only by a background color must have a 3:1 contrast ratio to the adjacent background"라고 한다. 같은 문서는 "If a control has visible content (such as text or a sufficiently contrasting icon) ... a border or other indication of the overall boundary of the hit area is not required"라고도 한다. 입력창 안의 안내 문구를 이 "visible content"로 인정하는지는 문서에 없다(확인하지 못함).
  - 예외 이유(사용자): 누르면 키보드가 올라와 입력 위치가 바로 확인된다. 검은 보내기 버튼(18.88:1), 안내 문구(4.76:1), 화면 아래 고정 위치도 입력창이 있다는 단서다.
  - B안(회색 면 + `#8C8C8C` 테두리, 흰 바탕 3.36:1·면 3.00:1)과 C안(흰 면 + 테두리)을 비교 그림으로 보고 A안을 골랐다. `--color-border-strong`은 쓰지 않으므로 토큰 블록에 없다. 대비 표의 `#8C8C8C` 행은 비교용이다.
  - 보완: 포커스 링은 흰 바탕과 면 회색 모두에서 3:1 이상이어야 한다(대비 표). 사용자 화면 확인(계획 Task 8)과 가벼운 사용자 테스트(Task 10)에서 입력창을 바로 찾는지 본다.
  - 타일·추천 카드·근거 박스도 면만 유지한다. 아이콘과 글자(또는 위치·글자 모양)로 알아본다. W3C 같은 문서의 Figure 30은 "A button which has a distinguishing indicator such as position, text style, or context does not need a contrasting visual indicator"를 통과 예로 든다.

## 3. 글꼴과 글자 크기

- 글꼴: **Pretendard**를 먼저, 없으면 기기 기본 한글 글꼴이다.
  - `--font-sans: "Pretendard", -apple-system, BlinkMacSystemFont, "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif`
  - 공식 배포물(npm `pretendard@1.3.9`)의 웹 글꼴을 저장소에서 자체 호스팅하고 `LICENSE`를 함께 둔다. 직접 잘라 쓰지 않는다(예약 글꼴 이름 때문, 결정기록 024). 굵기는 400·600·700 세 파일만 쓴다.
  - `font-display: swap`을 쓰고, 대체 글꼴로 넘어갈 때 줄이 크게 밀리지 않게 한다.
  - 부분 집합 종류: **`woff2-subset`의 Regular·SemiBold·Bold**(사용자 결정 2026-11-10, 결정기록 024). 빠지는 12자는 기기 기본 글꼴로 보인다.
- 한글 줄바꿈: `word-break: keep-all`. 글자 간격은 살짝 좁게(`letter-spacing: -0.2px`).

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--space-1` | `4px` | 아이콘과 글자 사이 |
| `--space-2` | `8px` | 타일·추천 카드 사이, 라벨과 값 사이 |
| `--space-3` | `12px` | 카드 안 요소 사이 |
| `--space-4` | `16px` | 화면 좌우 여백, 카드 안쪽 여백 |
| `--space-6` | `24px` | 영역 사이 |
| `--space-8` | `32px` | 랜딩 위아래 |
| `--radius-sm` | `8px` | 근거 박스, 작은 요소 |
| `--radius-md` | `16px` | 타일, 추천 카드, 대화 카드, 말풍선 |
| `--radius-pill` | `999px` | 검은 알약 버튼, 회색 알약 입력창, 보내기 동그라미 |
| `--tap-min` | `44px` | 누를 수 있는 모든 요소의 최소 높이·너비 |
| `--content-max` | `640px` | 넓은 화면에서 본문 최대 폭(가운데 정렬) |
| `--focus-ring` | `0 0 0 2px var(--color-bg), 0 0 0 4px var(--color-text)` | 키보드 포커스 표시(흰 바탕·면 회색·검은 버튼 위 모두 3:1 이상, 2절 대비 표, `outline`을 없애지 않고 함께 씀) |

- 그림자는 쓰지 않는다. 면은 `--color-surface`로, 경계는 `--color-border`로 나눈다.

## 5. 움직임

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--motion-fast` | `150ms ease` | 버튼 색 바뀜 |
| `--motion-slide` | `250ms ease` | 서랍 열고 닫기, 근거 펼침·접힘 |

- **동작 줄이기:** `@media (prefers-reduced-motion: reduce)`에서는 슬라이드·펼침 효과와 `transition`·`animation`을 모두 끄고 바로 바뀌게 한다. 옆으로 넘기기는 부드러운 스크롤 대신 바로 이동한다(`scroll-behavior: auto`).
- 로딩은 움직이는 그림 대신 "설명서를 펴 보는 중…" 글자로 보여 준다. 진행 표시도 동작 줄이기 설정을 따른다.

## 6. 부품별 모양

화면 흐름은 설계 2절(랜딩 → 카테고리 → 모델 → 채팅, ☰ 서랍)이다. 부품의 모양만 적는다.

1. **검은 알약 버튼:** `--color-action` 바탕, `--color-on-action` 글자 16px/600, `--radius-pill`, 높이 `--tap-min` 이상. 누르면 `--color-action-hover`. 로딩·잠금 중에는 `disabled`로 두고 `--color-surface` 바탕에 `--color-text-muted` 글자로 바꾼다.
2. **회색 알약 입력창:** `--color-surface` 바탕(테두리 없음, 2절의 예외), `--radius-pill`, 높이 48px 이상, 글자 16px 이상. 안내 문구는 `--color-text-muted`이고 예시를 넣는다(레퍼런스 3). 오른쪽에 검은 동그라미 보내기 버튼(`--tap-min` 이상). 화면 아래에 고정하고 안쪽 여백은 기기 안전 영역(`env(safe-area-inset-bottom)`)을 더한다.
3. **회색 네모 타일(카테고리):** `--color-surface`, `--radius-md`, 아이콘 + 이름. 가로 한 줄로 옆으로 넘기고 마지막 타일이 반쯤 보이게 한다. 아래에 점 표시를 둔다. 화살표 키로 넘길 수 있고 점도 눌러서 이동할 수 있다. 아직 없는 카테고리는 흐리게 "곧 추가"로 쓰고 누를 수 없게 한다.
4. **회색 추천 카드(채팅 비었을 때):** `--color-surface`, `--radius-md`, 굵은 첫 줄(600)과 `--color-text-muted` 둘째 줄. 옆으로 넘긴다(타일과 같은 규칙).
5. **가로 스크롤 규칙:** 카테고리 타일과 추천 카드만 옆으로 넘긴다. 나머지 화면은 폭 360px에서 가로 스크롤이 없다. 넘기는 영역은 키보드로 초점을 받고 화살표 키로 움직인다.
6. **말풍선과 답:** 내 질문은 오른쪽 `--color-surface` 말풍선(가린 질문으로 표시). 답은 말풍선 없이 본문(`--leading-body`). 앞 대화가 있을 때만 위에 `'○○'로 찾았어요`(`--text-sm`, muted)를 둔다.
7. **근거 박스** (레퍼런스 1·2): 가장 최근 답만 펼친다. `--color-surface` 바탕, `--radius-sm`, 왼쪽 선은 두지 않는다.
   - 위쪽에 출처 라벨(`--text-note`, 600). 설명서는 "사용설명서 32쪽", 가이드는 "공식 해결 가이드: 제목".
   - 아래에 인용 1~2문장(150자 이내). 설명서 원문을 통째로 보여 주지 않는다.
   - 에러 코드 질문이면 코드를 크게, 뜻을 [대괄호 라벨]로 붙이는 2단 표기(예: "OE" / "[배수 문제]").
   - 이전 답의 근거는 "이전 답 · 근거 N개" 한 줄로 접고, 누르면 펼친다.
   - **공식 링크:** 글자 링크, 새 탭, `rel="noopener"`. 문구는 1차 그대로.
8. **공용 가이드 경고:** 근거 박스 안 맨 아래, 아이콘 + 굵은 라벨 + "공용 콘텐츠라 모델에 따라 다를 수 있어요"(기획서 문구). 색 토큰은 따로 없다(2절).
9. **찾지 못함:** 답과 같은 모양이고 근거 박스는 없다. "설명서에서 찾지 못했어요" 다음에 `official_url`로 가는 "공식 고객센터에서 찾아보기" 링크. 정직한 답이므로 오류 색을 쓰지 않는다.
10. **오류:** `--color-error-bg`, `--color-error-text`, `--radius-md`, 앞에 아이콘. 서버의 `message`를 그대로 보여 주고 "다시 시도" 버튼(검은 알약)을 둔다.
11. **개인정보 안내** (`pii_masked`): 입력창 바로 위에 `--color-surface` 한 줄, 아이콘 + 굵은 라벨 "개인정보 안내".
12. **하단 고지:** `--text-xs`, muted. "비영리 학습용 포트폴리오 · 설명서 저작권은 각 제조사"
13. **아이콘:** Tabler Icons(MIT)의 SVG를 저장소에 두고 쓴다. 사용 조건은 결정기록 024에 있다. 아이콘만 있는 버튼에는 `aria-label`을 붙인다.
