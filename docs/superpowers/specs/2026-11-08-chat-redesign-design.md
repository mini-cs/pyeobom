# 펴봄 채팅형 개편 설계 (v1.5 — 1차 확장)

> 작성 2026-11-08 · 상태: 확정(사용자 승인) · 저장 위치(예정): `docs/superpowers/specs/2026-11-08-chat-redesign-design.md`
> 근거: 이 채팅의 브레인스토밍(질문·초안 화면·결정), 1차 결정기록 001~020

## 0. 목적과 범위

**성격:** 1차는 제출·발표까지 끝났고, 이번 작업은 **1차에서 이어지는 확장(v1.5)**이다. 2차(로그인 등)는 별도로 진행한다.

**목적:** 1차(검색형 단일 질문)를 **이어지는 질문까지 이해하는 채팅형 서비스**로 바꾸고, 랜딩 → 카테고리 → 모델 → 채팅 흐름과 새 디자인 체계를 도입한다.

**이번 범위**
- 새 화면 흐름과 디자인(흑백, Pretendard)
- 이어지는 질문 이해(질문 바꾸기 단계)
- 대화를 브라우저에 저장하고 지난 대화를 카드로 보여 주기
- 개편 전에 **1차 기준값**을 도구 6개로 측정

**하지 않을 것**
- 로그인, 서버에 대화 저장 (원래 2차 계획 — 브라우저 저장 형식에 버전을 붙여 나중에 옮길 수 있게만 함)
- 설명서 자동 수집 (제조사 협력이 현실적이지 않음, 약관·저작권)
- 새 카테고리(냉장고 등) 실제 추가 — 화면에는 "곧 추가" 자리만

## 1. 결정 요약

| 주제 | 결정 |
| --- | --- |
| 화면 흐름 | 랜딩(매번) → 카테고리 → 모델 → 채팅 |
| 카테고리 | 네모 아이콘 타일, 가로 한 줄, 옆으로 넘기기 |
| 모델 선택 | 별도 화면, 세 모델 모두 같은 스타일 **일러스트** + 공식 사이트 링크 |
| 채팅 기억 | 이어지는 질문까지 이해 (방법 A: 질문을 완성 문장으로 바꾼 뒤 검색) |

| 글꼴·크기 | Pretendard, 28/17/16/14/12px 체계 |
| 측정 도구 | DeepEval, Langfuse, Lighthouse, axe-core, Locust, Promptfoo |

## 2. 화면 흐름과 화면별 구성

흐름: **① 랜딩 → ② 카테고리 → ③ 모델 → ④ 채팅**, 어느 화면에서든 ☰로 **⑤ 지난 대화 서랍**

**① 랜딩 (방문할 때마다 첫 화면)**
- 큰 제목 "가전 설명서, 대신 펴 봐 드려요", 한 줄 설명
- 아이콘 + 굵은 제목 + 회색 설명 3줄: 근거 쪽을 보여 줘요 / 모르면 모른다고 해요 / 개인정보는 적지 마세요
- 아래쪽 검은 알약 버튼 "시작하기", 작은 비영리·저작권 안내
- 최근 대화가 있으면 가장 최근 대화 카드 1개

**② 카테고리**
- 위쪽: ☰ + "펴봄"
- "어떤 가전이 궁금하세요?"
- 네모 아이콘 타일 가로 한 줄, 옆으로 넘기기(마지막 타일이 반쯤 보이게, 점 표시). 세탁기·에어컨 + 흐린 "곧 추가"
- 아래: 최근 대화 카드 2~3개

**③ 모델 선택 (별도 화면)**
- 카드마다: 일러스트, 모델 이름, "모델명 찾는 법"(1차 문구 재사용), "공식 사이트에서 제품 보기" 링크
- 세탁기 2장(삼성, LG), 에어컨 1장

**④ 채팅**
- 위쪽: ☰ + 모델 이름, 오른쪽 검은 알약 "새 대화"
- 대화 없을 때: 가운데 비움, 아래쪽 회색 추천 카드(굵은 첫 줄 + 회색 둘째 줄) 옆으로 넘기기
- 내 질문: 오른쪽 회색 말풍선(가린 질문으로 표시)
- 답: 말풍선 없이 본문. 위에 "'○○'로 찾았어요"(바꾼 질문, 앞 대화가 있을 때만)
- 근거: 가장 최근 답만 펼침(쪽·제목·인용·공식 링크), 이전 답은 "이전 답 · 근거 N개" 한 줄로 접힘
- 아래쪽 고정: 회색 알약 입력창 + 검은 동그라미 보내기, "앞 대화를 기억해요 · 모델을 바꾸면 새 대화"
- 1차 상태 유지: 찾는 중, 찾지 못함(+공식 고객센터), 오류 카드 + 다시 시도, 개인정보 안내, 연타 방지

**⑤ 지난 대화 서랍**
- 대화 카드: 첫 질문(가린 문장), 모델, 날짜
- 누르면 그 대화로 돌아가 이어서 질문
- "새 대화", 대화마다 삭제, 전체 삭제(한 번 더 확인)
- 안내: "대화는 이 기기에만 저장돼요. 공용 기기라면 다 쓴 뒤 지워 주세요."

## 3. 디자인 체계

- **색:** 흰 바탕(#FFFFFF), 본문 검정(#111), 보조 회색(#7A7A7A), 면 회색(#F2F2F2 계열), 테두리(#DADADA 계열). 포인트 색 없음. 오류·개인정보 안내 색은 대비를 확인해 따로 정함
- **글꼴:** Pretendard (사용 조건은 도입할 때 공식 저장소에서 확인). 대체 글꼴: 기기 기본 한글 글꼴
- **글자 크기:** 큰 제목 28px/700, 위쪽 막대·모델 이름 17px/600, 본문·답·입력 16px, 보조·인용 14px, 작은 안내 12~13px, 버튼 16px/600. 본문 줄 간격 1.5~1.6, 글자 간격 살짝 좁게
- **입력창 16px 미만 금지** (아이폰 자동 확대 방지)
- **부품:** 검은 알약 버튼, 회색 알약 입력창, 회색 네모 타일(모서리 둥글게), 회색 추천 카드
- **접근성(1차 기준 유지):** 360px 먼저, 키보드로 모든 조작(가로 넘기기는 화살표 키), "동작 줄이기"면 슬라이드·펼침 효과 끔, 색 대비 WCAG AA

## 4. 제품 그림 정책

- **세 모델 모두 직접 만든 일러스트**로 통일(로고 없이 생김새만), 카드에 공식 사이트 링크
- **제작:** 채팅 Claude가 SVG로 그린다(같은 선 굵기·크기·흑백 스타일). 저장 위치 `public/images/models/`
- 조사 결과(2026-11-08):
  - 삼성 뉴스룸: 직접 제작 이미지는 자유 이용, 워터마크 이미지 제한, 변형 금지. 2026년형 비스포크 AI 콤보 출시 기사 사진 있음(터치형·다이얼형 두 종류 중 하나만)
  - LG 뉴스룸: CCL 2.0, 비영리·개인 목적만. FX24GNG는 이전 세대 사진만, SQ06FA1WDS는 사진 없음
  - 판매 페이지 사진: 쓸 근거 없음
- 일관성·법적 위험·앞으로 추가할 모델을 고려해 일러스트로 결정
- 시안: docs/design/시안-2026-11-08.html (4·5번이 최종 스타일과 글자 체계)

## 5. 대화 기억과 브라우저 저장

- **대화 하나 = 모델 하나.** 모델을 바꾸면 새 대화
- **저장 위치:** 브라우저 저장소. 서버에는 대화를 저장하지 않음
- **저장 형식(버전 포함):**
  - 대화: `id`, `model_id`, `title`(첫 질문 앞부분), `created_at`, `updated_at`
  - 메시지: `question_masked`, `rewritten_question`, `answer`, `found`, `citations`(쪽·제목·인용·링크)
- **개인정보:** 서버가 돌려준 **가린 질문만** 저장하고 화면에도 가린 질문을 보여 줌
- **한도(시작값, 측정 후 조정):** 대화 20개, 대화당 질문 30개. 넘치면 오래된 것부터 삭제
- **저장 실패**(시크릿 모드, 공간 부족): 화면에서는 계속 진행, "이 대화는 저장되지 않아요" 안내
- **서버로 보내는 앞 대화:** 최근 3번의 질문(가린 것)과 답 본문. 근거 원문은 보내지 않음

## 6. 서버 변경

**요청 (`POST /api/ask`)**
- 기존: `model_id`, `question`
- 추가(선택): `history`: `[{question, answer}]` 최대 3개, 질문 500자·답 1,000자 제한. 형식 오류는 `INVALID_REQUEST`
- `history`가 없으면 1차와 동일하게 동작 (기존 평가로 회귀 확인 가능)

**처리 순서**
1. 입력 검사(1차 규칙 그대로) → 새 질문과 `history` 모두 개인정보 가리기
2. `history`가 있으면 **질문 바꾸기**: 전용 프롬프트로 "혼자 읽어도 이해되는 한 문장"을 JSON으로 받음
   - 규칙: 앞 대화의 주제만 보충, 새 정보 추가 금지, 이미 완전하면 그대로, 주제가 바뀌면 앞 대화 무시
   - 실패·시간 초과(짧은 제한, 측정으로 정함) → 원래 질문 사용
3. 바뀐 질문으로 1차 검색(모델 필터, v2a 진단 안내 규칙 그대로)
4. **답변 AI에는 앞 대화를 넘기지 않음.** 바뀐 질문 + 설명서 조각만 (앞의 답을 근거처럼 쓰는 것을 막기 위해)
5. 1차 인용 검증 그대로 → 실패 시 1회 재요청 → 그래도 실패면 찾지 못함

**응답 추가 항목:** `question_masked`, `rewritten_question`(앞 대화가 있을 때), debug 시 `rewrite_ms`

**기록:** 1차처럼 질문 원문은 서버 기록에 남기지 않음

## 7. 평가

**① 회귀: 1차 고정 30문항(앞 대화 없이)**
- 기준: 1차 v2a 대비 변동 폭(30개 중 2개) 안, 환각 0

**② 새 세트: 이어지는 질문 약 12개 대화(대화당 2~3번 질문)**
- 유형: 가리키는 말("그건"), 생략("그럼 해결은요?"), 주제 바꾸기, 이어지는 함정(설명서에 없는 내용), 개인정보가 든 후속 질문
- 측정: 질문 바꾸기 정확도(사람 판정), 정답률(사람 판정), 환각, 근거 적중, 응답 시간·비용 증가

**채택 조건 (측정 전에 확정, 측정 후 변경 금지)**
1. 회귀 30문항: 변동 폭 안, 환각 0
2. 새 세트: 질문 바꾸기 정확도와 정답률 각 80% 이상, 환각 0
3. 평균 응답 시간 증가 1.5초 이내
   - (2026-11-09 변경, 계획 3부터 적용, 결정기록 028) 비교 대상은 **같은 실행 안의 앞 대화 없는 질문**이다. 다른 날 잰 기준값과 비교하지 않는다. 계획 2는 원래 정의(1차 기준값 대비)로 재서 +1,509ms였고 명시적 예외로 채택했다.

**화면 확인:** 360px, 키보드만, 동작 줄이기, 시크릿 모드, 대화·전체 삭제

## 8. 1차 기준값 측정 (개편 착수 전)

1차 상태(태그 v1.0)를 아래 도구로 재서 `docs/평가/baseline-v1.md`에 남기고, 개편 후 같은 방법으로 다시 잰다.

| 도구 | 재는 것 | 대상·방법 |
| --- | --- | --- |
| DeepEval | 충실도, 답변 관련성, 근거 관련성 등 | 1차 30문항, pytest에 연결. 사람 판정과 나란히 기록(보조 지표) |
| Langfuse | 단계별 시간·토큰·비용 | 무료 클라우드, 1차 30문항 한 번 실행 추적 |
| Lighthouse | LCP, CLS, TBT 등 실험실 점수 | 운영 첫 화면, 모바일 설정, 3회 실행 중앙값 |
| axe-core + Playwright | 접근성 위반 수 | 1차 화면의 주요 상태(빈 화면, 답, 찾지 못함, 오류) |
| Locust | 동시 요청 시 응답 시간(중앙값·상위 5%·1%), 오류율 | **미리보기에서만**, 작은 부하(시작값: 동시 5명, 1분) |
| Promptfoo | 프롬프트 인젝션·개인정보 빼내기 등 레드팀 결과 | 미리보기 API 대상, 시나리오 수 제한 |

**비용 관리:** 도구 자체는 모두 무료(오픈소스·무료 플랜)다. 비용은 DeepEval·Promptfoo의 AI 채점·공격 생성, Locust의 실제 질문 호출이 쓰는 **OpenAI API 사용량**뿐이며, 기존 OpenAI 선불 잔액에서 나간다(별도 결제 없음, 잔액이 부족할 때만 충전 필요). 운영 서비스와 같은 잔액을 쓰므로 측정이 잔액을 바닥내면 운영이 멈춘다. 그래서 실행 전 잔액을 확인하고, 예상 비용을 계산해 기록하고, 합계 상한 **2달러**(선불 5달러 중 일부, 나머지는 운영용으로 남김)를 넘지 않게 한다. 비밀 값(키)은 도구 설정에도 `.env`로만 넣는다.

**스킬 활용:** Claude Code에 find-skills를 설치해 도구별 설정 스킬을 **찾기만** 하고, 공식 출처이거나 설치 수가 충분한 것만 SKILL.md를 읽은 뒤 설치한다.

## 9. 배포

- 작업은 새 브랜치, 확인은 **미리보기에서만**
- 착수 전 1차 상태에 **태그 v1.0**, 1차 마지막 운영 배포의 **고유 주소를 기록**해 포트폴리오에서 1차 화면을 계속 보여 줄 수 있게 한다(제출한 시연 영상·발표 자료와 대응)
- 1차 평가는 끝났으므로, **7번 채택 조건을 충족하면 운영에 반영**한다

## 11. 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 질문 바꾸기가 뜻을 바꿈 | "이렇게 이해했어요" 표시, 새 정보 추가 금지 규칙, 새 평가 세트로 측정 |
| 앞의 답이 근거처럼 쓰임 | 답변 AI에 앞 대화를 넘기지 않음, 1차 인용 검증 유지 |
| 브라우저에 개인정보 잔류 | 가린 질문만 저장, 삭제 기능, 공용 기기 안내 |
| 응답 시간 증가 | 질문 바꾸기 시간 제한, Langfuse로 단계별 측정, 채택 조건 3 |
| 글꼴 때문에 첫 화면 느려짐 | Lighthouse 전후 비교, 필요하면 글꼴 일부만 불러오기 |
| 측정 도구 비용 | 실행 전 예상 비용 계산, 합계 상한 |
| 운영 화면이 제출물과 달라짐 | 평가 기간 끝까지 운영 반영 금지 |
