# 2차 Task 11 ② 실제 흐름 테스트 — 실제 메일 코드 로그인 → 요청 → 다른 계정에서는 안 보임 (짧은 설계)

- 날짜: 2026-11-27
- 상태: 확정(사용자 승인 2026-11-27)
- 관련: 2차 설계 `docs/superpowers/specs/2026-11-17-phase2-model-request-design.md` 3.7-6(시험 계정은 Resend 받기 주소, 코드는 받기 API로 읽음)·10절(안정성 시연)·11절(Playwright QA 메뉴), 2차 계획 `docs/superpowers/plans/2026-11-21-phase2-model-request-plan.md` Task 11·덧붙임 A-5(U10)·Global 11·12, 기존 실제 RLS 테스트 `tests/requests/test_rls_live.py`, "내 요청" 설계 `docs/superpowers/specs/2026-11-27-my-requests-design.md`
- 크기: 테스트 파일 하나와 설정 설명(앱 코드 변경 없음). Task 11의 세 가지 중 둘째

## 왜

- 2차 메뉴 "Playwright QA"의 핵심: 실제 브라우저로 로그인 → 요청 → 방어 장면을 자동으로 확인한다(설계 11절)
- 실제 Supabase RLS는 API 수준에서 이미 확인했다(`tests/requests/test_rls_live.py`, 2026-11-25 8개 통과). 이 테스트는 실제 메일 코드 로그인과 "내 요청" 화면까지 이어서 확인하고, 시연 영상 재료를 남긴다

## 목표

1. 실제 운영 주소에서, 실제 메일로 받은 코드로 A가 로그인해 요청하고, 첫 화면 "내 요청"에서 그 요청을 본다
2. B로 로그인하면 A의 요청이 보이지 않는다(RLS 장면)
3. 실제 DB·Supabase가 막는 방어 장면 두 가지가 화면에 맞게 나온다
4. 테스트가 끝나면 자기가 만든 계정과 요청만 남김없이 지운다

## 하지 않을 것

- 앱 코드(`public/`·`app/`)를 바꾸지 않는다. 질문은 하지 않는다(OpenAI 0원)
- 구글 로그인은 자동화하지 않는다(테스트 목록 밖 구글 계정 로그인 확인은 이 테스트 범위 밖)
- 기본 테스트 실행(`pytest -m "not integration"`)에 들어가지 않는다
- 화면 안 검사(빈 입력·이미 있는 모델 등)는 가짜 Supabase 테스트가 이미 확인하므로 다시 하지 않는다

## 실패로 볼 것

- Resend 받기 주소의 계정 id(받기 도메인)나 전체 권한 키가 출력·실패 문구·보고·저장소·영상에 남는다
- 테스트가 자기가 만들지 않은 계정·요청을 지운다
- 테스트가 끝난 뒤 시험 계정이 운영에 남는데 테스트가 성공으로 끝난다

## 접근

- 고름: **pytest + Playwright(파이썬, 기존 `integration` 표시) 테스트 파일 하나.** 받기 API·계정 정리는 httpx(기존 실제 RLS 테스트와 같은 방식)
- 고르지 않음: 노드 Playwright 테스트 도구(새 도구·설정이 생기고 기존 도우미를 못 씀), Resend CLI·MCP로 코드 읽기(사람용 도구, 따로 설치)

## 정한 것 (사용자 결정 2026-11-27)

1. 두 계정(A·B) 모두 실제 메일 코드로 로그인한다(Resend 받기 주소, 설계 3.7-6 그대로)
2. 운영 주소(`https://pyeobom.help`)에 대고 돌린다. 이번 PR은 테스트만 더해 앱 코드가 운영과 같다. 미리보기와 운영은 같은 Supabase를 쓰므로 어느 쪽이든 시험 계정·요청은 같은 곳에 생긴다
3. 끝나면 테스트가 자기가 만든 두 계정만 관리 키로 지운다(요청은 계정과 함께 지워짐, `on delete cascade`). 지우기가 하나라도 실패하면 테스트가 실패로 알린다
4. 녹화한다. 녹화 중에는 받기 주소가 보이는 글자를 가린다(칸 모양은 남기고 글자만 안 보이게). 영상은 git 밖에 두고 채팅 Claude가 영상에 주소가 보이지 않는지 확인한다

## 흐름 (휴대폰 크기 화면 390×844)

1. A: 첫 화면 → [시작하기] → 건조기 → [내 모델이 없어요] → 로그인 시트에 A 받기 주소 → [코드 보내기] → 받기 API에서 그 주소로 온 코드 메일을 찾아 코드를 읽어 입력 → 요청 화면에서 브랜드 `가짜브랜드`, 모델명 `E2E-<돌린 시각>`(돌릴 때마다 다름) → [요청하기] → `요청을 받았어요. 추가되면 메일로 알려 드릴게요.`
2. 방어 장면 ①: A로 같은 모델명을 한 번 더 요청 → `이미 요청하셨어요`(DB 같은 사람·같은 모델 제약)
3. A의 "내 요청": 첫 화면에 `내 요청 1건` → 누르면 그 요청이 `대기`로 한 줄
4. 로그아웃(서랍 계정 줄) → 로그인 시트에 B 받기 주소 → [코드 보내기] → 방어 장면 ②: 틀린 코드 한 번 → `코드가 맞지 않아요. 다시 확인해 주세요` → 받기 API로 읽은 코드로 로그인
5. B의 첫 화면에 "내 요청" 요약 줄이 없고, `#requests`는 `아직 요청이 없어요`(RLS 장면)
6. 정리: 두 계정을 관리 키로 지운다

## 채팅 Claude가 정한 것 (읽으며 고칠 수 있음)

1. 받기 주소는 돌릴 때마다 새로 만든다: `e2e-a-<무작위 8자>@<받기 도메인>`, `e2e-b-<무작위 8자>@<받기 도메인>`(같은 주소 60초 제한·지난 실행 메일과 섞이지 않게)
2. 로컬 `.env`의 새 이름 두 개(로컬에만, Vercel에는 넣지 않음): `RESEND_RECEIVING_API_KEY`(U10의 전체 권한 키), `RESEND_RECEIVING_DOMAIN`(`<계정 id>.resend.app`). 대상 주소는 `E2E_BASE_URL`(비면 `https://pyeobom.help`). 셋 중 키·도메인이 없으면 테스트를 건너뛴다. `VERCEL_AUTOMATION_BYPASS_SECRET`이 있으면 `x-vercel-protection-bypass` 머리글을 붙인다(나중에 미리보기에서 돌릴 때를 위해, Vercel 문서 "Protection Bypass for Automation")
3. 코드 읽기: `GET https://api.resend.com/emails/receiving`로 목록을 받아 `to`에 그 주소가 있고 이번 실행 뒤에 온 메일을 찾고, `GET /emails/receiving/{id}`의 `text`(없으면 `html`)에서 숫자 6~10자리를 읽는다(덧붙임 A-2). 2초마다 최대 90초 기다린다(Resend 문서 2026-11-27 확인)
4. 정리: 계정 id는 이 실행의 받기 주소로 관리 API 사용자 목록에서 찾는다(코드 단계에서 실패해도 만들어진 계정을 지울 수 있게). 지운 수를 개수로만 보고한다
5. 출력 금지: 받기 주소·도메인·키·코드·user_id를 print·로그·실패 문구·보고에 넣지 않는다. 메일이 보이는 요소(`#request-email`·`#drawer-email` 등)에 대한 확인 문구를 쓰지 않는다. Playwright 추적(trace)·실패 사진은 끈다
6. 녹화 중 가리기: 테스트가 페이지에 스타일을 넣어 받기 주소가 보이는 칸과 글자(로그인 시트 이메일 칸·"보낸 이메일"·요청 화면 계정 상자·서랍 계정 줄·계정 바꾸기 창)의 글자색을 투명하게 한다. 앱 코드는 바꾸지 않는다
7. 영상: `docs/Claude outputs/phase2/e2e/`(git 밖)에 한 실행에 한 파일. 채팅 Claude가 영상의 장면을 뽑아 주소가 보이지 않는지 확인한 뒤에만 시연 영상에 쓴다
8. 돌리는 횟수: 지금 한 번(실패하면 원인을 보고하고 멈춤, 다시 돌리기는 사용자 확인 뒤). Resend 약 5통(코드 보내기 2 + 받기 2 + 운영자 알림 1, 같은 모델 다시 요청은 DB에서 막혀 알림 없음), OpenAI 0원. 장부는 AI 비용만 적으므로 줄을 더하지 않는다
9. `pytest.ini`의 `integration` 설명을 "실제 외부 서비스(OpenAI·Neon·Supabase·Resend)에 연결하는 테스트"로 넓힌다(계획 Task 11 그대로, 새 표시 이름 없음)
10. 브랜치 `feat/phase2-live-flow-test`, PR 하나(Task 11을 세 부분으로 나눠 함)
