# 로그인 상태 보이기 — 짧은 설계 (2차 Task 6 덧붙임)

- 날짜: 2026-11-25
- 상태: 사용자 결정(비교 그림을 보고 고름, 2026-11-25). 쓴 사람: Claude Code(채팅 Claude 지시 블록을 옮김)
- 관련: 계획 `docs/superpowers/plans/2026-11-21-phase2-model-request-plan.md` Task 6·덧붙임 D, 디자인 가이드 `docs/design/디자인-가이드.md` 6절

## 왜·목표

미리보기 실제 시험(2026-11-25)에서 사용자가 구글로 로그인한 뒤 로그인됐는지 알 수 없었다. 구글 메일과 코드 메일이 다르면 계정이 둘 생길 수 있어, 요청하기 전에 **"알림 받을 메일"**을 보여야 한다.

- 요청 화면에서 지금 로그인한 메일(= 알림 받을 메일)을 보이고, 그 자리에서 계정을 바꿀 수 있게 한다.
- 서랍에서도 로그인 상태(메일)와 로그아웃을 보인다.

## 하지 않는 것

- 프로필 사진(구글 사진 등)
- 두 계정 합치기
- 첫 화면 "내 요청" 카드(계획 Task 11, 목표)

## 피할 것

- 첫 화면에서 공개 설정·Supabase 부르기(기존 첫 화면 테스트 그대로)
- 메일 주소를 저장소·로그에 남기기(화면에만 보인다)

## 고른 안과 뺀 안

| 안 | 내용 | 결과 |
|---|---|---|
| **A1** | 요청 화면 "가전 종류" 아래에 계정 상자(알림 받을 메일 + 바꾸기) | **고름** |
| A2 | 요청 화면에는 메일만, 바꾸기는 서랍에서 | 뺌: 계정을 바꾸려면 서랍까지 가야 함 |
| B | 로그인 직후 잠깐 뜨는 알림 | 뺌: 잠깐 떴다 사라짐 |
| C1 | 서랍 맨 위 계정 줄 | 뺌: "지난 대화"가 밀림 |
| **C2** | 서랍 맨 아래(하단 고지 바로 위) 계정 줄 | **고름** |
| V1 | 바꾸기 = 흰 알약 글자 버튼(채팅 Claude 추천) | 뺌(사용자가 V3를 고름) |
| V2 | 바꾸기 = 상자 전체를 누름 + 꺾쇠 | 뺌(사용자가 V3를 고름) |
| **V3** | 바꾸기 = 상자 오른쪽 동그라미 아이콘 버튼 | **고름** |

## 동작

- **계정 바꾸기:** 로그아웃 없이 로그인 시트(1단계, 맨 위 이유 문구 그대로)만 연다. 새 로그인이 끝나면 그 세션으로 바뀌고 요청 화면으로 돌아와 상자 메일이 새 메일로 바뀐다. 시트를 닫으면 원래 계정 그대로다(채팅 Claude 제안, 사용자 결정).
- **서랍 계정 줄:** 서랍을 열 때 로그인 상태를 읽는다. 로그인 상태면 동그라미 글자 + 메일 + [로그아웃], 로그인 전이면 같은 자리에 [로그인].
- **동그라미 글자:** 메일 첫 글자를 대문자로. 프로필 사진은 쓰지 않는다(채팅 Claude 제안, 사용자 결정).

## 모양 (디자인 가이드 변수만)

- **계정 상자(A1·V3):** `--color-surface` 둥근 상자(개인정보 안내·요청 받음 상자와 같은 모서리·여백). 왼쪽 Tabler `mail` 아이콘(장식), 가운데 "알림 받을 메일"(`--color-text-muted`, 작은 글자) 아래 메일(굵게, 넘치면 말줄임, 전체 메일은 화면 낭독기가 읽음), 오른쪽 지름 36px `--color-bg` 동그라미 안 Tabler `arrows-exchange` 아이콘 버튼("계정 바꾸기" — `aria-label`·`title`, 누르는 영역 `--tap-min` 이상, hover·focus 상태).
- **서랍 계정 줄(C2):** 위에 `--color-border` 구분선. 지름 32px `--color-action` 동그라미 안 메일 첫 글자 대문자(`--color-on-action`, 장식), 메일(굵게, 말줄임), [로그아웃].

## 덧붙임 (2026-11-25): 로그인 방식 표시(L1)와 계정 바꾸기 확인 창(S1)

### 배경

사용자가 미리보기에서 계정 바꾸기를 실제로 확인했다(6단계 모두 기대대로). 두 가지를 짚었다.

1. 구글 계정인지 메일 코드 계정인지 화면에 안 나온다(이번 시험의 두 메일이 한 글자만 달라 헷갈림).
2. [계정 바꾸기]를 누르면 처음 로그인과 같은 창이 바로 뜨고 이메일 칸에 이전 메일이 채워져 있다.

### 고른 안과 뺀 안 (사용자가 비교 그림을 보고 고름, 문구는 채팅 Claude 제안·사용자 확인)

| 안 | 내용 | 결과 |
|---|---|---|
| **L1** | 작은 회색 글자로 로그인 방식("Google 계정"·"메일 코드 계정") | **고름** |
| L2 | 메일 옆 꼬리표 | 뺌: 좁은 화면에서 메일이 더 일찍 잘림 |
| **S1** | [계정 바꾸기] → 확인 창 → 빈 로그인 창 | **고름** |
| S3 | [계정 바꾸기] → 메뉴(바꾸기·로그아웃) | 뺌: 로그아웃이 서랍과 겹치고 고를 게 늘어남 |

### 화면·문구

- **로그인 방식(L1):** 구글로 로그인 → "Google 계정", 메일 코드로 로그인 → "메일 코드 계정", 알 수 없으면 표시 안 함.
  - 요청 화면 상자: 작은 글자 줄을 "알림 받을 메일 · Google 계정"처럼.
  - 서랍 계정 줄: 메일 아래에 작은 회색 글자(`--color-text-muted`)로 "Google 계정".
  - 지금 방식은 세션 토큰의 `amr`(가장 최근 방식이 맨 앞)로 안다. `app_metadata.provider`는 처음 가입 방식, `providers`는 묶인 방식 목록이라 같은 메일로 두 방식이 한 계정에 묶이면 지금 방식을 알 수 없다(Supabase 문서 auth-mfa·jwt-fields·users·identity linking, 2026-11-25 확인).
- **계정 바꾸기(S1):**
  1. [계정 바꾸기] → 확인 창(서랍 "전체 삭제" 확인 창과 같은 모양): 제목 "다른 계정으로 바꿀까요?", 회색 작은 상자 "지금 계정 · <로그인 방식>" + 지금 메일(굵게), 설명 "바꾸면 앞으로 알림은 새 계정 메일로 가요. 지금까지 한 요청은 지금 계정에 남아요.", 버튼 [취소] [바꾸기]. 열리면 창 안으로 포커스, Esc·[취소]는 닫고 포커스를 [계정 바꾸기]로 돌려준다.
  2. [바꾸기] → 로그인 시트를 "바꾸기" 모양으로: 제목 "다른 계정으로 로그인", 맨 위 안내 "새 계정으로 로그인하면 알림을 그 메일로 보내 드려요", 이메일 칸은 비움, [Google로 계속하기]와 개인정보 안내는 그대로. 로그아웃하지 않는다. 시트를 닫으면 지금 계정 그대로, 새 로그인이 끝나면 요청 화면으로 돌아와 상자의 메일·방식이 바뀐다.
- 처음 로그인 시트(제목 "로그인", 이유 문구)는 그대로. 시트를 새로 열 때 이메일 칸은 늘 비우고, 2단계의 [수정]으로 돌아올 때만 적은 메일을 남긴다.

### Google G 로고를 계정 표시에 쓰지 않는 이유

Google 지침(developers.google.com/identity/branding-guidelines)은 로그인 버튼을 다룬 것이라, 로그인한 계정을 표시하는 데 G 로고를 써도 되는지는 확인하지 못했다. 그래서 계정 표시는 글자("Google 계정")만 쓴다.
