# 서랍에 뒤로·처음으로 버튼 — 짧은 설계

- 날짜: 2026-11-13 · 크기: 작은 변경(짧은 설계) · 승인: 사용자 2026-11-13 채팅
- 근거: `docs/평가/v15-ui.md` 결과(2026-11-13) "다른 가전으로 가는 길", 결정기록 021 재검토 조건

## 왜
사용자 테스트에서 B·D(4명 중 2명)가 홈 버튼이 없다고 했다. 지금 다른 가전으로 가려면 ☰ 안의 "새 대화"나 브라우저 뒤로 가기를 써야 한다. 결정기록 021의 재검토 조건(첫 질문까지 가는 길이 번거롭다는 응답)에 해당한다.

## 목표 · 하지 않는 것 · 실패로 볼 것
- 목표: 가전 고르기·모델 고르기·채팅 화면에서 한 단계 위 화면과 첫 화면으로 가는 버튼을 둔다.
- 하지 않는 것: 위쪽 막대는 바꾸지 않는다. "새 대화" 두 개(서랍 = 가전 고르기로, 채팅 막대 = 같은 모델로 새로)의 이름 정리는 다음 계획 후보로 둔다. 첫 화면은 바꾸지 않는다.
- 실패로 볼 것: ←를 눌러도 서랍만 닫히는 것, 버튼이 겹치거나 누르는 자리가 44px보다 작은 것, 이동 뒤 포커스가 사라지는 것.

## 고려한 방법 (360px 채팅 화면, 폭은 지금 스타일 값으로 계산한 추정)
- A 위쪽 막대 한 줄에 ←·⌂ 추가: 고칠 양이 가장 적다. 모델 이름 자리가 약 84px라 "삼성 BESPOKE AI 콤보"(약 145px)가 잘린다.
- B A + "새 대화"를 + 아이콘으로: 이름 자리 약 132~148px로 아슬아슬하다. "새 대화" 글자가 사라진다.
- C 막대에 버튼 다섯 개 + 이름을 둘째 줄로: 모두 보이지만 막대가 약 32px 높아진다.
- E ←는 막대, ⌂만 서랍(채팅 Claude 추천): 뒤로가 늘 보인다. 이름이 한 글자쯤 잘릴 수 있다.
- D ←·⌂ 모두 서랍 맨 윗줄(선택): 막대와 모델 이름이 지금 그대로다. 위험: 테스트 때와 막대가 같아 보여 같은 지적이 다시 나올 수 있고, 뒤로가 두 번 누르기(☰ → ←)가 된다. 사용자가 이 위험을 듣고 골랐고, 아래 "다음 테스트 기준"으로 확인한다.

## 정한 것 (사용자 결정)
1. ☰ "지난 대화" 서랍 맨 윗줄: 왼쪽 [←][⌂], 오른쪽 [✕]. "지난 대화" 제목은 그 아래 줄.
2. ← = 한 단계 위: 채팅 → 그 가전의 모델 고르기, 모델 고르기 → 가전 고르기. 가전 고르기에서는 ←를 숨긴다(⌂와 같아서).
3. ⌂ = 첫 화면(소개).
4. ✕ = 서랍 닫기. 지금의 "닫기" 글자 버튼을 바꾼다.
5. ←·⌂를 누르면 서랍이 닫히고 그 화면으로 간다.
6. 세 버튼 모두 아이콘만 둔다. 화면 읽기용 이름은 "뒤로", "처음으로", "닫기".

## 확인 방법
- 360px·1280px에서 세 화면(가전 고르기·모델 고르기·채팅)의 서랍 캡처
- 키보드: 탭 순서 ← → ⌂ → ✕, Esc로 닫힘
- 기존 테스트 모두 통과
- 배포 뒤 운영 화면에서 확인
