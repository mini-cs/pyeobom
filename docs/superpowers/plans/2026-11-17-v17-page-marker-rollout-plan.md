- 상태: **초안, 실행하지 않음.** 사용자 확인 뒤 별도 브랜치(예: `feat/v17-page-marker-rollout`)로 진행한다.
- 근거: 결정기록 032(쪽 표시 지우기 채택), 리포트 `docs/평가/v17-extraction.md`
- 영향 점검: 2026-11-17, 운영 DB 조회(SELECT)와 코드 검색만. AI 호출 없음, 비용 0
- 보완(2026-11-17, 사용자 결정 ②③): 지우기 전 백업, 넣은 뒤 임베딩 대조, 30문항 합격선(측정 전 확정)

## 무엇을 바꾸나

- `ingest/load.py`의 `build_chunks` 설명서 경로만 바꾼다. 쪽 글에 `clean_text` 다음 `strip_page_marker(글, 쪽)`(앞 20자만, 끝 검사 끔)을 적용한다. 측정한 "쪽 표시만 지운 것"(`strip_800`)과 같은 흐름이다(pypdfium2 → clean_text → 쪽 표시 지우기 → 800자/100자 겹침).
- 가이드(HTML) 경로는 그대로 둔다.
- app/(검색·답변·화면)은 바꾸지 않는다. Vercel에 새로 배포할 코드는 없다.

## 단계

1. **테스트 먼저**(커밋 두 번): `build_chunks`가 설명서 쪽 글의 쪽 표시를 지우고, 가이드는 바꾸지 않는다는 테스트(`extract_pages`를 바꿔 끼운 단위 테스트) → 실패 확인 커밋 → 구현 커밋. `ingest/page_marker.py` 맨 위 설명("운영 적재에는 연결하지 않는다")도 고친다.
2. **오프라인 대조(비용 0)**: 새 `build_chunks`로 만든 설명서 3개의 조각(쪽 번호와 글)이 실험 조각 `bundle_chunks`의 `strip_800` 설명서 조각과 순서·쪽 번호·글자까지 같은지 확인한다(SELECT만). 다르면 멈추고 보고한다.
3. **장부**: 임베딩 예상 약 0.005달러(설명서 조각 297개, 약 16만 3천 자 × 2e-8 ≈ 0.0033달러에 여유)를 적고 `check_budget`을 통과한다. 잔액이 1달러 넘게 남는지 확인한다.
4. **넣기 전 대조**: 다시 넣으면 `documents`·`document_models`가 `data/documents.json` 값으로 덮인다(`ingest/load.py` `save`). 운영 행과 파일 값이 같은지 SELECT로 대조하고, 다르면 멈추고 보고한다.
5. **지우기 전 백업(비용 0, SELECT만)**
   - 내보낼 것:
     - 설명서 3개의 운영 조각: 조각 번호, 문서, 쪽, 문서 안 순서, 글
     - `chunk_variants` 가운데 설명서 조각을 가리키는 행(2026-11-17 기준 1,555행 = `m1_title` 297 + `m2_question` 1,258)
   - 저장 위치: `measure/out/v17-rollout-backup/`(git 밖, 설명서 글이 들어 있음). 리포트에는 행 수와 파일 해시만 적는다.
   - 목적:
     - AI로 만든 질문(`m2_question` 1,258행)을 다시 만드는 비용을 아낀다.
     - 확인용 세트를 정식으로 열 때 옛 조각 번호를 새 번호로 맞춘다(사용자 결정 ②).
     - 되돌릴 때 비교한다.
   - 행 수가 위와 다르면 멈추고 보고한다.
6. **다시 넣기(데이터 삭제, 실행 전 사용자 확인)**: `python -m ingest --doc-id manual-samsung-wd90h25`, `manual-lg-fx25`, `manual-lg-sq06fa1wds`. 문서마다 한 트랜잭션으로 기존 조각을 지우고 새로 넣는다.
7. **넣은 뒤 조회(비용 0)**
   - 설명서별 조각 수(지금 118·101·78, 실험 `strip_800`도 설명서 297개), 가이드 조각 번호 298~335가 그대로인지, 전체 조각 수를 SELECT로 확인한다.
   - **임베딩 대조**: 새 설명서 조각을 `bundle_chunks` `strip_800`의 설명서 조각과 (문서, 문서 안 순서)로 짝짓는다(2단계에서 글이 같음을 확인한 짝). pgvector 코사인 거리(`<=>`)로 유사도(1 − 거리)를 재고 최솟값·평균을 기록한다. 0.99 아래가 하나라도 있으면 멈추고 보고한다.
8. **운영 확인(장부에 적은 뒤 1회)**: 평가 세트에 없는 질문 1개를 운영 주소로 보내 근거가 붙는지 본다(예상 0.0008달러 이하).
9. **운영 30문항 회귀**: `python -m evaluation --label v17-rollout-r1`·`-r2`로 두 번 돌려 ⑰을 적용한다(예상 약 0.022~0.044달러).
   - **합격선(사용자 결정 ③, 2026-11-17, 측정 전 확정)**: ⑰ 정답 24/30 이상이고 환각 0이면 통과다. Task 11 운영 그대로 26에서 허용 폭 2를 뺀 값으로, 설계 7절 회귀 기준과 같다.
   - 판정은 사람이 전부 한다. 판정 기준은 Task 11 최종 판정과 같다. 한 벌만 보는 확인이라 가린 판정지는 쓰지 않는다. 환각은 자동 채점(`hallucinated`는 함정에서 찾음일 때만 잡음)으로 세지 않는다.
   - 못 넘으면 결정기록 032 "다시 볼 조건"대로 다시 본다. 되돌릴지는 사용자가 정한다.
   - 한계: Task 11과 같은 실행 안 비교가 아니다.
10. 결정기록 032에 반영 결과를 덧붙이고 개발일지에 PR 링크를 적는다.
