- 근거: 결정기록 032(쪽 표시 지우기 채택), 리포트 `docs/평가/v17-extraction.md`
- 영향 점검: 2026-11-17, 운영 DB 조회(SELECT)와 코드 검색만. AI 호출 없음, 비용 0

## 무엇을 바꾸나

- `ingest/load.py`의 `build_chunks` 설명서 경로만 바꾼다. 쪽 글에 `clean_text` 다음 `strip_page_marker(글, 쪽)`(앞 20자만, 끝 검사 끔)을 적용한다. 측정한 "쪽 표시만 지운 것"(`strip_800`)과 같은 흐름이다(pypdfium2 → clean_text → 쪽 표시 지우기 → 800자/100자 겹침).
- 가이드(HTML) 경로는 그대로 둔다.
- app/(검색·답변·화면)은 바꾸지 않는다. Vercel에 새로 배포할 코드는 없다.

## 단계

1. **테스트 먼저**(커밋 두 번): `build_chunks`가 설명서 쪽 글의 쪽 표시를 지우고, 가이드는 바꾸지 않는다는 테스트(`extract_pages`를 바꿔 끼운 단위 테스트) → 실패 확인 커밋 → 구현 커밋.
2. **오프라인 대조(비용 0)**: 새 `build_chunks`로 만든 설명서 3개의 조각 글이 실험 조각 `bundle_chunks`의 `strip_800` 설명서 조각 글과 순서·글자까지 같은지 확인한다(SELECT만). 다르면 멈추고 보고한다.
3. **장부**: 임베딩 예상 약 0.005달러(설명서 조각 297개, 약 16만 3천 자 × 2e-8 ≈ 0.0033달러에 여유)를 적고 `check_budget`을 통과한다. 잔액이 1달러 넘게 남는지 확인한다.
4. **다시 넣기(데이터 삭제, 실행 전 사용자 확인)**: `python -m ingest --doc-id manual-samsung-wd90h25`, `manual-lg-fx25`, `manual-lg-sq06fa1wds`. 문서마다 한 트랜잭션으로 기존 조각을 지우고 새로 넣는다.
5. **넣은 뒤 조회**: 설명서별 조각 수(지금 118·101·78, 실험 `strip_800`도 설명서 297개), 가이드 조각 번호 298~335가 그대로인지, 전체 조각 수를 SELECT로 확인한다.
6. **운영 확인(장부에 적은 뒤 1회)**: 평가 세트에 없는 질문 1개를 운영 주소로 보내 근거가 붙는지 본다(예상 0.0008달러 이하).
7. **운영 30문항 회귀**: `python -m evaluation --label v17-rollout`으로 1회 돌린다(예상 약 0.011~0.022달러). 환각이 나오면 결정기록 032의 "다시 볼 조건"대로 다시 본다.
8. 결정기록 032에 반영 결과를 덧붙이고 개발일지에 PR 링크를 적는다.
